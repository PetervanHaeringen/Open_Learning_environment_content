# Module 1 — What is Software Testing?

Welcome to the TestGarden! In this first module you'll learn what testing actually is,
why it matters so much, and how you as a tester add value to software projects.
Everything is practical, concrete, and immediately applicable.

## 1. What is software testing?

Software testing means: **investigating whether software works the way the user expects**.
You try to find bugs before the users do. A tester is really a
professional explorer with a critical eye.
It's not just about hunting for mistakes — it's also about learning to see how software actually behaves.

- You check whether functions do what they're supposed to do.
- You think like a real user, even one who makes mistakes.
- You prevent frustration, damage, wasted time, and even safety problems.

Testing, then, is not a side activity — it's an essential part of software quality.

## 2. Why is testing important?

Bugs in software can have serious consequences. From small irritations
to major problems like data leaks, broken transactions, or financial damage.

By testing early, you prevent problems later. A bug discovered in production
can be *10 to 100 times more expensive* than the same bug caught early.

### Example

A webshop where the payment page doesn't work.
→ Customers buy nothing → The company loses out on thousands of euros.
A simple test could have caught this early.

## 3. The role of the tester

As a tester, you're the guardian of quality. You work together with developers, designers,
and product owners. You see what a user sees.

- You ask critical questions: does this really work as intended?
- You think about risks: what if this page fails?
- You make problems clear with good bug reports.

You don't need to be a programmer. You mainly need to be curious, precise, and creative.

## 4. Practical assignment: Bug Hunt!

Time to activate your tester eyes! You're going to spend 10 minutes on
[parabank.parasoft.com](https://parabank.parasoft.com/parabank/index.htm)
looking for anything that isn't quite right.

### Assignment

1. Find at least 5 possible problems or strange things:
   - buttons that do nothing
   - errors in texts
   - elements that jump around
   - pages that load slowly
   - something that feels illogical
2. Note them briefly in bullet points.

> **Tip:** There's no such thing as a "silly" finding. Anything that's confusing,
> slow, wrong, or ugly counts.

## 5. Reflection

Think back on what you found:

- Which bug did you find the most striking?
- What would the effect have been if this bug had never been discovered?

You'll use these insights in the coming modules.
