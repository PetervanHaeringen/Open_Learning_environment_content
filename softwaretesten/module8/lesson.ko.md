# 모듈 8 – 자동화와 AI 테스팅

이 모듈에서는 현대 소프트웨어 테스팅의 두 가지 큰 흐름을 접하게 됩니다:

- 테스트 자동화
- AI 지원 테스팅(AI-assisted testing)

소프트웨어 개발은 빠르게 변화하고 있습니다.
AI 시스템은 코드를 작성하고, 테스트를 생성하고, 로그를 분석하며, 테스터의 업무를 지원합니다.

하지만 동시에 새로운 과제도 등장합니다:

> 항상 정확히 똑같이 반응하지는 않는 시스템을 어떻게 검증할 것인가?

그래서 테스터의 역할은 다음에서:
- 단순히 확인하는 것
다음으로 서서히 옮겨가고 있습니다:
- 관찰하기
- 평가하기
- 해석하기
- 비판적으로 사고하기

---

## 1. 테스트 자동화란 무엇인가?

테스트 자동화란 테스트가 스크립트나 도구에 의해 자동으로 실행되는 것을 의미합니다.

같은 단계를 계속 수동으로 수행하는 대신, 소프트웨어가 이를 반복하게 합니다.

자주 자동화되는 것들:

- 스모크 테스트
- 회귀 테스트
- API 점검
- 엔드투엔드 흐름
- 성능 점검

### 왜 자동화하는가?

자동화는 다음에 도움이 됩니다:
- 더 빠르게 피드백을 받는 것
- 반복 가능하게 테스트하는 것
- 인간의 실수를 줄이는 것
- 더 자주 테스트하는 것

### 보통 자동화하지 않는 것은?

일부 형태의 테스트는 여전히 강하게 인간에 의존합니다:

- 탐색적 테스트
- 사용성(usability)
- 창의성
- 공감
- 맥락 이해
- 예상치 못한 상황 인식

> 자동화는 테스터를 강화합니다.
> 테스터의 통찰력을 대체하지는 않습니다.

---

## 2. 자동화를 위한 현대적인 도구들

자주 사용되는 도구:

- **Playwright**
- **Cypress**
- **Selenium**
- **Postman**
- GitHub Actions와 같은 CI/CD 파이프라인

### 자동화의 예

스크립트는 자동으로 다음을 할 수 있습니다:

1. 웹사이트를 연다
2. 로그인한다
3. 양식을 채운다
4. 무언가가 보이는지 확인한다
5. 오류를 보고한다

이것은 새로운 릴리스가 있을 때마다 빠른 회귀 테스트를 가능하게 합니다.

---

## 3. AI 지원 테스팅

AI는 테스팅을 지원하는 데 점점 더 많이 사용되고 있습니다.

예를 들어 다음을 위해서입니다:

- 테스트 케이스 생성
- 로그 요약
- 오류 패턴 인식
- 회귀 위험 예측
- 테스트 데이터 생성
- 자동 문서 작성

### 하지만 주의하세요

AI의 출력은 종종 설득력 있게 들립니다.

그렇다고 해서 자동으로 그것이 옳다는 뜻은 아닙니다.

AI는 다음과 같은 일을 할 수 있습니다:
- 잘못된 가정을 함
- 세부사항을 지어냄
- 중요한 시나리오를 놓침
- 일관성 없는 답변을 줌

그래서 인간의 감독은 여전히 필수적입니다.

> 훌륭한 테스터는 AI를 맹목적으로 신뢰하지 않습니다.
> 그들은 AI를 비판적으로 사용합니다.

---

## 4. 결정론적 시스템 vs 확률적 시스템

전통적인 소프트웨어는 보통 결정론적(deterministic)으로 작동합니다.

즉:

```text
같은 입력 → 같은 출력
```

AI 시스템에서는 종종 다르게 작동합니다.

거대 언어 모델이나 추천 시스템은 다음과 같이 반응할 수 있습니다:

```text
같은 입력 → 서로 다른 가능한 출력들
```

이것을 확률적(probabilistic) 행동이라고 부릅니다.

### 왜 이것이 중요한가?

이로 인해 테스트하는 방식 자체가 바뀌기 때문입니다.

전통적인 소프트웨어에서는 주로 다음을 확인합니다:

- 정확한 결과
- 고정된 규칙
- 예측 가능한 결과

AI 시스템에서는 더 자주 다음을 평가합니다:

- 품질
- 일관성
- 합리성
- 안전성
- 편향(bias)
- 맥락 민감도

---

## 5. AI 출력을 비판적으로 평가하기

AI 시스템은 설득력 있게 들리면서도 여전히 실수를 할 수 있습니다.

그래서 테스터로서 당신은 다음을 확인합니다:

- 정보가 정확한가?
- 시스템이 주어진 작업 범위 안에 머무르는가?
- 환각(hallucination)이 발생하는가?
- 출력이 안전한가?
- 시스템이 안정적으로 반응하는가?
- 사용자를 공정하게 대하는가?

### 환각(Hallucinations)

AI는 다음과 같은 정보를 생성할 수 있습니다:
- 그럴듯하게 들리지만
- 사실은 틀린 정보

예를 들면:
- 지어낸 출처
- 존재하지 않는 기능
- 잘못된 결론
- 부정확한 요약

그래서 테스터는 다음을 배워야 합니다:

> "논리적으로 들린다"는 것이 "정확하다"는 것과 같지는 않습니다.

---

## 6. AI 시스템의 주요 위험 요소

### 편향(Bias)

시스템이 서로 다른 사용자 그룹을 공정하게 대하는가?

### 드리프트(Drift)

새로운 데이터로 인해 행동이 서서히 변화하는가?

### 프롬프트 민감도(Prompt sensitivity)

표현의 작은 변화가 갑자기 완전히 다른 답변을 만들어내는가?

### 안전성

다음과 같은 경우에 무슨 일이 일어나는가:
- 이상한 입력
- 조작적인 프롬프트
- 극단적인 상황?

### 설명 가능성(Explainability)

시스템이 왜 그렇게 행동하는지 당신이 이해할 수 있는가?

---

## 7. 실제 현장에서 AI 테스트하기

AI 테스팅은 종종 전통적인 점검보다는 연구를 수행하는 것에 더 가깝습니다.

당신은 다음을 다룹니다:
- 가설
- 관찰
- 출력 비교
- 패턴 인식

### AI 테스트의 예시

- 시스템이 일관된 답변을 주는가?
- 모순되는 정보에 어떻게 반응하는가?
- 불완전한 입력을 처리할 수 있는가?
- 차별적인 패턴이 나타나는가?
- 오용에 안전하게 반응하는가?

---

## 8. 실습 과제: AI 기능 조사하기

이제 당신은 AI 시스템을 비판적으로 조사해 봅니다.

### 과제

1. AI 기능을 하나 선택하세요:
   - 챗봇
   - 이미지 인식기
   - 추천 시스템
   - AI 어시스턴트

2. 최소 5개의 테스트를 고안하세요:
   - 일반적인 시나리오 2개
   - 경계 사례 2개
   - 공정성/편향 테스트 1개

3. 각 테스트마다 다음을 기록하세요:
   - 입력
   - 예상 행동
   - 실제 행동

4. 다음을 분석하세요:
   - 예측 가능성
   - 일관성
   - 안전성
   - 공정성

- 사용자에게 어떤 위험이 있다고 보이나요?
- 어떤 역할이 여전히 인간의 몫으로 남는다고 생각하나요?
- AI는 테스터의 역할을 어떻게 바꾸고 있나요?

> 어쩌면 앞으로 테스팅은 점점 더:
>
> "작동하는가?"
>
> 에서:
>
> "책임감 있고, 이해 가능하며, 신뢰할 수 있게 행동하는가?"
>
> 로 옮겨가고 있는지도 모릅니다.
