# 模块10 — 黑盒测试技术

到目前为止，你主要学习的是*要*进行测试。而这个模块要讲的是*如何*聪明地选择*测试什么*。因为你不可能测试所有东西——通常，可能的输入是无穷无尽的。真正的功夫，在于用一小组精心挑选的测试用例，就能找到大部分的错误。

---

## 1. 黑盒测试：不看代码进行测试

在**黑盒测试**中，你把程序当作一个黑盒子来对待：你知道输入什么、应该得到什么输出，但你不去看盒子里面的代码。你测试的是，程序的行为是否符合承诺——也就是规格说明（specification）。

与之相对的是**白盒测试**，在白盒测试中，你确实会去看内部代码，从而决定测什么。这两者各有各的用武之地。黑盒测试之所以强大，是因为即使内部代码被完全重写，只要对外承诺的行为保持不变，你的测试用例依然有效。

在这个模块中，我们会介绍四种常用的黑盒技术：
- 等价类
- 边界值分析
- 判定表
- 状态转换

---

## 2. 等价类：被同等对待的一组输入

想象一下：某个网站只允许18岁及以上的人创建账号。年龄可以从0到大约120岁不等。难道你要把这121个年龄全都测一遍吗？不用。

**等价类**背后的想法是：程序会以完全相同的方式对待一大组输入。对于这个年龄校验来说，实际上只有两个组：
- **太年轻**：0到17岁（会被拒绝）
- **年龄够了**：18到120岁（会被接受）

在每个组内部，选哪个值并不重要——如果25岁能通过，40岁大概率也能通过。所以，你只需要每组测一个值。比如，年龄10（太年轻）和年龄30（年龄够了）。用两个测试用例，代替了121个。

**有效等价类**包含那些应该被接受的值，**无效等价类**包含那些应该被拒绝的值。重要的是：不要忘了无效等价类。一个能妥善处理正常输入、但一遇到错误输入就崩溃的程序，仍然是有问题的。

---

## 3. 边界值分析：错误常常出现在边缘

程序员犯错，往往不是在一组数据的中间，而是在两组之间的**边界**上。到底是`>= 18`还是`> 18`？这一年之差，恰恰是最容易出错的地方。

因此，**边界值分析（BVA）**专注于等价类的边缘。在18岁这个年龄边界上，有意思的值是：

- **17**——刚好太年轻（被拒绝组中的最后一个值）
- **18**——刚好够格（被接受组中的第一个值）

通过精确测试这两个值，你能抓住那个经典的"刚好符合／刚好不符合"的错误。如果程序员不小心把`>= 18`写成了`> 18`，一个18岁的人就会被错误地拒绝——而你在18岁这个点上的测试，正好能抓住这个问题。

有些测试人员还会再往外多测一步（16、17、18，或17、18、19），以求更加保险。你纳入的边界值越多，测试就越彻底——但工作量也越大。这是一个需要权衡的取舍。

注意：边界值分析只适用于**有顺序**的输入，也就是"大于"和"小于"有意义的输入——比如数字、日期、金额。对于没有顺序的输入（比如在红、绿、蓝之间做选择），是不存在边界的。

---

## 4. 判定表：当多个条件同时起作用时

有时候，一个程序的行为取决于多个条件的组合。比如，一个网店按照以下规则给出折扣：
- 是否是会员俱乐部的成员？**并且**
- 订单是否超过50欧元？

有两个条件，每个都可能为真或为假，那就有四种组合。**判定表**能把这些整齐地列出来：

| 是会员吗？ | 超过50欧元吗？ | 折扣 |
|------|----------------|---------|
| 是   | 是             | 10%     |
| 是   | 否             | 5%      |
| 否   | 是             | 无      |
| 否   | 否             | 无      |

每一列（或者说，在这种排列方式下的每一行）就是一条你要测试的独立规则。判定表的强大之处在于，你能系统地把*所有*组合都过一遍——包括那些如果不用这种方法、你可能会遗漏的组合。而且，制作这张表本身也会迫使你去审视：这些规则是否真的完整、没有相互矛盾。

两个条件，就有四种组合；三个条件，就有八种；四个条件，就有十六种——每多一个条件，组合数就翻一倍。当条件很多时，这会变得难以处理，于是你就要根据风险，选出最重要的那些组合来测试。

---

## 5. 状态转换：取决于历史的行为

有些系统的表现，会根据它们当前所处的位置——也就是它们的**状态**——而有所不同。想想一个简单的红绿灯：红灯 → 绿灯 → 黄灯 → 红灯。或者一份网上订单：*草稿 → 已下单 → 已发货 → 已送达*。

在**状态转换测试**中，你要测试的是：当某件事发生时（一个*事件*），系统是否能干净利落地从一个状态转移到另一个状态——而同样重要的是：面对被禁止的操作时，系统是否*不会*发生状态转换。

举个例子：一份已经发货的订单，不应该还能被取消。这就是一个**无效的转换**。一个优秀的测试人员，恰恰会去尝试这些被禁止的步骤，因为那里往往藏着最危险的bug：一个允许取消已发货包裹的系统，可能会导致真正的问题。

所以，你要测试两件事：
- **有效的转换**：它们是否都正确地发生了？
- **无效的转换**：它们是否都被妥善地拒绝了？

---

## 6. 什么时候用哪种技术？

没有哪一种技术是"最好的"——它们是相互补充的：
- 当存在一组被同等对待的输入时，用**等价类**。
- 一旦涉及有顺序的边界（年龄、金额、日期），就用**边界值分析**。
- 当行为取决于多个条件的组合时，用**判定表**。
- 当行为取决于系统当前所处的位置时，用**状态转换**。

在实践中，你会把它们结合起来使用。对于年龄校验，你会同时使用等价类和边界值。一个经验丰富的测试人员，能凭直觉感知到哪种技术适合哪种问题——而这种直觉，是通过不断练习培养出来的。
