# 모듈 7 – API 테스팅

이 모듈에서는 API 테스팅의 기초를 배웁니다.

많은 소프트웨어는 API를 통해 서로 통신하는 구성 요소들로 이루어져 있습니다.

테스터로서, 당신은 Postman 같은 도구를 사용해 이 API들을 직접 점검할 수 있습니다.
이것은 테스트를:
- 더 빠르게
- 더 정확하게
- 더 강력하게
만들어줍니다.

---

## 1. API란 무엇인가?

API는 다음을 의미합니다:

> **애플리케이션 프로그래밍 인터페이스(Application Programming Interface)**

API란 소프트웨어 구성 요소들이 서로 통신하는 방식입니다.

API를 테스트할 때, 당신은 예를 들어 다음을 확인합니다:

- GET 요청 시 무슨 일이 일어나는지
- POST/PUT 요청 시 무슨 일이 일어나는지
- 어떤 오류 메시지가 반환되는지
- JSON 구조가 올바른지
- 서버가 얼마나 빠르게 응답하는지

### 예시

한 온라인 쇼핑몰 앱이 다음과 같이 요청합니다:

> "도서 카테고리에 있는 모든 상품을 알려주세요."

그러면 서버는 JSON 데이터를 돌려보냅니다.

---

## 2. HTTP 상태 코드

모든 API 응답에는 상태 코드가 포함되어 있습니다.

이것은 요청이 성공했는지를 알려줍니다.

### 자주 사용되는 상태 코드

- **200** — OK(성공)
- **201** — Created(생성됨)
- **400** — Bad Request(잘못된 요청)
- **401** — Unauthorized(인증되지 않음)
- **404** — Not Found(찾을 수 없음)
- **500** — Server Error(서버 오류)

> 500 상태 코드는 보통 백엔드의 버그를 가리킵니다.

---

## 3. JSON: API의 언어

많은 API는 JSON을 사용해 통신합니다.

JSON은 구조화된 텍스트 데이터입니다.

### 예시

```json
{
  "id": 42,
  "name": "테스트 상품",
  "price": 9.99
}
```

### API 테스트 중에 당신은 다음을 확인합니다:

- 모든 필드가 존재하는가?
- 값이 올바른가?
- 누락된 데이터가 있는가?
- 예상치 못한 데이터가 있는가?

---

## 4. Postman으로 API 테스트하기

Postman은 API 테스팅에 널리 사용되는 도구입니다.

이것을 사용해 다음을 테스트할 수 있습니다:

- 엔드포인트(endpoint)가 존재하는지
- API가 오류에 어떻게 반응하는지
- 응답 시간(response time)
- JSON 구조

### 기본 요청

1. Postman을 엽니다
2. 메서드를 선택합니다: GET
3. URL을 입력합니다:
   `https://example.com/api/products`
4. Send를 클릭합니다
5. 다음을 확인합니다:
   - 상태 코드
   - 헤더(headers)
   - 본문(body)

---

## 5. 기본 API 체크리스트

API 테스트 중에는 이 체크리스트를 사용하세요.

- [ ] 엔드포인트가 존재함 (404가 아님)
- [ ] 유효한 입력에 대해 올바른 응답
- [ ] 유효하지 않은 입력에 대해 올바른 응답
- [ ] JSON 구조가 올바름
- [ ] 값들이 논리적임
- [ ] 응답 시간이 허용 범위 내임

---

## 6. 실습 과제: API 점검 6가지

이제 당신은 직접 6가지 API 테스트를 실행합니다.

### 과제

1. 공개된 API나 데모용 API를 하나 선택하세요.
2. 긍정 테스트(positive test) 3개를 실행하세요.
3. 부정 테스트(negative test) 3개를 실행하세요.
4. 다음을 기록하세요:
   - 상태 코드
   - 응답 시간
   - 응답 본문
5. 발견한 이상 현상이나 버그를 설명하세요.

> 오류 코드가 항상 잘못된 것을 의미하지는 않습니다.
> 오히려 API가 제대로 응답하고 있다는 것을 보여주는 경우가 많습니다.
