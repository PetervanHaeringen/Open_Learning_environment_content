# Модуль 7 – Тестирование API

В этом модуле вы изучите основы тестирования API.

Большая часть программного обеспечения состоит из компонентов, которые взаимодействуют друг с другом через API.

Как тестировщик, вы можете напрямую проверять эти API с помощью таких инструментов, как Postman.
Это делает тестирование:
- быстрее
- точнее
- мощнее

---

## 1. Что такое API?

API означает:

> **Application Programming Interface** (Программный интерфейс приложения)

API — это способ, с помощью которого компоненты программного обеспечения взаимодействуют друг с другом.

Когда вы тестируете API, вы проверяете, например:

- что происходит при GET-запросах
- что происходит при POST/PUT-запросах
- какие сообщения об ошибках возвращаются
- корректна ли структура JSON
- насколько быстро отвечает сервер

### Пример

Приложение интернет-магазина запрашивает:

> «Дай мне все товары из категории книги».

Сервер затем отправляет обратно данные в формате JSON.

---

## 2. HTTP-коды состояния

Каждый ответ API содержит код состояния (status code).

Он показывает, был ли запрос успешным.

### Часто используемые коды состояния

- **200** — OK (Успешно)
- **201** — Created (Создано)
- **400** — Bad Request (Неверный запрос)
- **401** — Unauthorized (Не авторизован)
- **404** — Not Found (Не найдено)
- **500** — Server Error (Ошибка сервера)

> Код состояния 500 обычно указывает на ошибку в бэкенде.

---

## 3. JSON: язык API

Многие API взаимодействуют с помощью JSON.

JSON — это структурированные текстовые данные.

### Пример

```json
{
  "id": 42,
  "name": "Тестовый товар",
  "price": 9.99
}
```

### Во время тестирования API вы проверяете:

- все ли поля присутствуют?
- правильны ли значения?
- отсутствуют ли какие-либо данные?
- есть ли неожиданные данные?

---

## 4. Тестирование API с помощью Postman

Postman — популярный инструмент для тестирования API.

С его помощью можно тестировать:

- существуют ли эндпоинты (endpoints)
- как API реагирует на ошибки
- время отклика (response times)
- структуры JSON

### Базовый запрос

1. Откройте Postman
2. Выберите метод: GET
3. Введите URL:
   `https://example.com/api/products`
4. Нажмите Send
5. Проверьте:
   - код состояния
   - заголовки (headers)
   - тело ответа (body)

---

## 5. Базовый чек-лист для API

Используйте этот чек-лист во время тестирования API.

- [ ] Эндпоинт существует (нет 404)
- [ ] Корректный ответ на валидные данные
- [ ] Корректный ответ на некорректные данные
- [ ] Структура JSON верна
- [ ] Значения логичны
- [ ] Время отклика приемлемо

---

## 6. Практическое задание: 6 проверок API

Теперь вы сами проведёте шесть тестов API.

### Задание

1. Выберите публичный API или демо-API.
2. Проведите три позитивных теста.
3. Проведите три негативных теста.
4. Запишите:
   - код состояния
   - время отклика
   - тело ответа
5. Опишите любые отклонения или баги.

> Коды ошибок не всегда означают, что что-то не так.
> Часто они как раз показывают, что API отвечает правильно.
