# الوحدة 7 – اختبار واجهات برمجة التطبيقات (API Testing)

في هذه الوحدة، ستتعلّم أساسيات اختبار واجهات برمجة التطبيقات (API).

يتألّف الكثير من البرمجيات من مكوّنات تتواصل مع بعضها البعض عبر واجهات برمجة التطبيقات (APIs).

بصفتك مختبِرًا، يمكنك فحص هذه الواجهات مباشرة باستخدام أدوات مثل Postman.
وهذا يجعل الاختبار:
- أسرع
- أكثر دقة
- أكثر قوة

---

## 1. ما هي واجهة برمجة التطبيقات (API)؟

API تعني:

> **واجهة برمجة التطبيقات (Application Programming Interface)**

الـ API هي وسيلة تتواصل بها مكوّنات البرمجيات مع بعضها البعض.

عندما تختبر واجهة API، فإنك تتحقّق مثلًا من:

- ماذا يحدث عند طلبات GET
- ماذا يحدث عند طلبات POST/PUT
- ما رسائل الخطأ التي تعود
- هل بنية JSON صحيحة
- ما مدى سرعة استجابة الخادم (server)

### مثال

يطلب تطبيق متجر إلكتروني:

> "أعطني كل المنتجات من فئة الكتب."

يقوم الخادم عندئذٍ بإرسال بيانات JSON استجابةً لذلك.

---

## 2. رموز حالة HTTP (HTTP Status Codes)

تحتوي كل استجابة API على رمز حالة (status code).

يخبرك هذا الرمز ما إذا كان الطلب قد نجح أم لا.

### رموز الحالة الأكثر استخدامًا

- **200** — نجاح (OK)
- **201** — تم الإنشاء (Created)
- **400** — طلب غير صحيح (Bad Request)
- **401** — غير مصرَّح (Unauthorized)
- **404** — غير موجود (Not Found)
- **500** — خطأ في الخادم (Server Error)

> يشير رمز الحالة 500 عادةً إلى خطأ في الواجهة الخلفية (backend).

---

## 3. JSON: لغة واجهات برمجة التطبيقات

تتواصل العديد من الـ APIs باستخدام JSON.

JSON هو بيانات نصية منظّمة.

### مثال

```json
{
  "id": 42,
  "name": "منتج اختباري",
  "price": 9.99
}
```

### أثناء اختبار API، تتحقّق من:

- هل جميع الحقول موجودة؟
- هل القيم صحيحة؟
- هل هناك بيانات مفقودة؟
- هل هناك بيانات غير متوقَّعة؟

---

## 4. اختبار واجهات API باستخدام Postman

Postman أداة شائعة لاختبار واجهات برمجة التطبيقات.

يمكنك من خلالها اختبار:

- ما إذا كانت نقاط النهاية (endpoints) موجودة
- كيف تستجيب الـ API للأخطاء
- أوقات الاستجابة (response times)
- بنى JSON

### طلب أساسي

1. افتح Postman
2. اختر الطريقة (method): GET
3. أدخل الرابط (URL):
   `https://example.com/api/products`
4. انقر على Send
5. راجع:
   - رمز الحالة (status code)
   - الترويسات (headers)
   - المتن (body)

---

## 5. قائمة تحقق أساسية لاختبار API

استخدم قائمة التحقق هذه أثناء اختبار API.

- [ ] نقطة النهاية (endpoint) موجودة (لا يوجد 404)
- [ ] استجابة صحيحة للمدخلات الصالحة
- [ ] استجابة صحيحة للمدخلات غير الصالحة
- [ ] بنية JSON صحيحة
- [ ] القيم منطقية
- [ ] وقت الاستجابة مقبول

---

## 6. تمرين عملي: 6 فحوصات لـ API

الآن ستُجري بنفسك ستة اختبارات لواجهة API.

### المهمة

1. اختر واجهة API عامة أو واجهة API تجريبية.
2. نفّذ ثلاثة اختبارات إيجابية.
3. نفّذ ثلاثة اختبارات سلبية.
4. دوّن:
   - رمز الحالة (status code)
   - وقت الاستجابة
   - متن الاستجابة (response body)
5. صِف أي انحرافات أو أخطاء.

> رموز الأخطاء ليست دائمًا أخطاءً.
> غالبًا ما تُظهر بالضبط أن الـ API تستجيب بشكل صحيح.

---

## 7. التأمّل الذاتي

فكّر مجددًا في اختباراتك:

- ما رموز الحالة التي رأيتها أكثر؟
- هل كانت الـ API قابلة للتنبؤ؟
- أي اختبار سلبي أعطى نتائج مثيرة للاهتمام؟
- أين يمكن أن يكمن خطر أمني؟
