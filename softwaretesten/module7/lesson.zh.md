# 模块7 — API测试（API Testing）

在这个模块中，你将学习API测试的基础知识。

许多软件都是由通过API相互通信的各个组件组成的。

作为测试人员，你可以使用Postman这样的工具，直接对这些API进行检查。
这会让测试变得：
- 更快
- 更精确
- 更强大

---

## 1. 什么是API？

API的意思是：

> **应用程序编程接口（Application Programming Interface）**

API是软件各组件之间相互通信的一种方式。

当你测试一个API时，你要检查的内容，例如包括：

- GET请求会发生什么
- POST/PUT请求会发生什么
- 会返回哪些错误提示
- JSON结构是否正确
- 服务器响应的速度有多快

### 举例

一个网店应用发出请求：

> "给我图书分类下的所有商品。"

服务器随后返回JSON格式的数据。

---

## 2. HTTP状态码

每一个API响应，都会带有一个状态码。

它告诉你，这次请求是否成功。

### 常见的状态码

- **200** — OK（成功）
- **201** — Created（已创建）
- **400** — Bad Request（请求错误）
- **401** — Unauthorized（未授权）
- **404** — Not Found（未找到）
- **500** — Server Error（服务器错误）

> 500状态码通常意味着后端出现了错误。

---

## 3. JSON：API的语言

许多API都使用JSON进行通信。

JSON是一种结构化的文本数据格式。

### 举例

```json
{
  "id": 42,
  "name": "测试商品",
  "price": 9.99
}
```

### 在API测试期间，你要检查：

- 所有字段是否都存在？
- 数值是否正确？
- 是否缺少数据？
- 是否出现了意料之外的数据？

---

## 4. 用Postman测试API

Postman是一款流行的API测试工具。

你可以用它来测试：

- 端点（endpoint）是否存在
- API在出错时的响应方式
- 响应时间
- JSON结构

### 基本请求

1. 打开Postman
2. 选择方法：GET
3. 输入URL：
   `https://example.com/api/products`
4. 点击"Send"
5. 查看：
   - 状态码
   - 请求头（headers）
   - 响应体（body）

---

## 5. API基础检查清单

在进行API测试时，使用这份检查清单。

- [ ] 端点存在（没有404错误）
- [ ] 对有效输入的响应正确
- [ ] 对无效输入的响应正确
- [ ] JSON结构正确
- [ ] 数值合理
- [ ] 响应时间可以接受

---

## 6. 实践作业：6项API检查

现在，你要亲自执行六个API测试。

### 作业内容

1. 选择一个公开的API或演示用的API。
2. 执行三个正向测试（positive test）。
3. 执行三个负向测试（negative test）。
4. 记录下：
   - 状态码
   - 响应时间
   - 响应体
5. 描述你发现的任何异常或bug。

> 错误代码并不总是意味着"出错了"。
> 很多时候，它们恰恰说明API正在正确地做出响应。

- 这个API的表现是否可预测？
- 哪个负向测试给出了有意思的结果？
- 哪里可能存在安全风险？
