# モジュール7 – APIテスト（API Testing）

このモジュールでは、APIテストの基礎を学びます。

多くのソフトウェアは、APIを介して互いに通信するコンポーネントから成り立っています。

テスターであるあなたは、Postmanのようなツールを使って、これらのAPIを直接チェックすることができます。
これによって、テストは：
- より速く
- より正確に
- より強力に
なります。

---

## 1. APIとは何か？

APIとは：

> **アプリケーション・プログラミング・インターフェース（Application Programming Interface）**

のことです。

APIとは、ソフトウェアのコンポーネント同士が互いに通信するための手段です。

APIをテストするとき、あなたは例えば次のことを確認します：

- GETリクエストで何が起こるか
- POST/PUTリクエストで何が起こるか
- どんなエラーメッセージが返ってくるか
- JSON構造が正しいかどうか
- サーバーがどれくらい速く応答するか

### 例

あるネットショップのアプリが、次のように問い合わせるとします：

> 「本のカテゴリーに属する商品をすべてください。」

すると、サーバーはJSONデータを返します。

---

## 2. HTTPステータスコード

すべてのAPIレスポンスには、ステータスコードが含まれています。

それは、そのリクエストが成功したかどうかを示すものです。

### よく使われるステータスコード

- **200** — OK（成功）
- **201** — Created（作成完了）
- **400** — Bad Request（不正なリクエスト）
- **401** — Unauthorized（認証されていない）
- **404** — Not Found（見つからない）
- **500** — Server Error（サーバーエラー）

> 500というステータスコードは、通常、バックエンド側のバグを示しています。

---

## 3. JSON：APIの言語

多くのAPIは、JSONを使って通信します。

JSONとは、構造化されたテキストデータのことです。

### 例

```json
{
  "id": 42,
  "name": "テスト商品",
  "price": 9.99
}
```

### APIテストの際には、次のことを確認します：

- すべてのフィールドが揃っているか？
- 値は正しいか？
- 何かデータが欠けていないか？
- 予期しないデータが含まれていないか？

---

## 4. Postmanを使ってAPIをテストする

Postmanは、APIテストのために広く使われているツールです。

これを使って、次のことをテストできます：

- エンドポイントが存在するかどうか
- APIがエラーにどう反応するか
- レスポンスタイム（応答時間）
- JSON構造

### 基本的なリクエスト

1. Postmanを開く
2. メソッドを選ぶ：GET
3. URLを入力する：
   `https://example.com/api/products`
4. 「Send」をクリックする
5. 次を確認する：
   - ステータスコード
   - ヘッダー
   - ボディ（本文）

---

## 5. 基本のAPIチェックリスト

APIテストの際には、このチェックリストを使ってください。

- [ ] エンドポイントが存在する（404にならない）
- [ ] 有効な入力に対して正しく応答する
- [ ] 無効な入力に対して正しく応答する
- [ ] JSON構造が正しい
- [ ] 値が理にかなっている
- [ ] レスポンスタイムが許容範囲内である

---

## 6. 実践課題：6つのAPIチェック

これから、あなた自身で6つのAPIテストを実行します。

### 課題

1. 公開されているAPI、またはデモ用のAPIを1つ選びます。
2. ポジティブテスト（正常系のテスト）を3回行います。
3. ネガティブテスト（異常系のテスト）を3回行います。
4. 次を記録します：
   - ステータスコード
   - レスポンスタイム
   - レスポンスボディ
5. 見つかった逸脱やバグについて記述します。

> エラーコードは、必ずしも「間違い」を意味するわけではありません。
> むしろ、APIが正しく応答していることを示している場合が多いのです。

---

## 7. ふりかえり

自分が行ったテストについて振り返ってみましょう：

- どのステータスコードを最もよく見ましたか？
- そのAPIは予測可能なものでしたか？
- どのネガティブテストが、興味深い結果を示しましたか？
- どこにセキュリティ上のリスクが潜んでいる可能性がありますか？
