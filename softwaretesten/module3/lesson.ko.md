# 모듈 3 – 테스트 계획과 위험 분석

이 모듈에서는 가벼운(lightweight) 테스트 계획의 기본을 배웁니다.

두꺼운 문서가 아니라, 다음 내용을 담은 실용적인 요약입니다:

**우리는 무엇을, 왜, 어떻게 테스트할 것이며, 언제 충분히 좋다고 할 수 있는가?**

---

## 1. 테스트 계획이란 무엇인가?

테스트 계획이란 테스트에 방향을 제시하는 짧은 문서입니다.

이것은 다음을 설명합니다:

- 무엇을 테스트해야 하는지
- 어떤 위험이 중요한지
- 어떤 접근 방식을 선택하는지

현대적인 프로젝트에서는, 그리고 물론 TestGarden에서도, 테스트 계획을 최대한 단순하게 유지합니다.

한 페이지면 충분한 경우가 많습니다.

### 테스트 계획에는 보통 다음이 포함됩니다

- 범위(Scope) — 무엇을 테스트하고, 무엇을 테스트하지 않는가?
- 주요 위험 요소
- 접근 방식 — 스모크 테스트, 테스트 케이스, 탐색적 테스트
- 테스트 환경
- 시작/종료 기준(Entry & Exit criteria)
- 역할 — 누가 무엇을 하는가?

---

## 2. 위험 기반 테스팅이란 무엇인가?

위험 요소는 어떤 부분을 테스트하는 것이 가장 중요한지 결정하는 데 도움이 됩니다.

위험은 **발생 가능한 버그**와 그 **영향력**이 결합될 때 생겨납니다.

우리는 간단한 공식을 사용합니다:

> **위험 = 발생 확률 × 영향력**

위험이 높을수록, 그 부분은 테스트 계획에서 더 많은 관심이 필요합니다.

### 온라인 쇼핑몰 예시

- "상품 보기" 페이지 → 영향력이 낮음
- "결제" 페이지 → 영향력이 높음

그래서 결제 프로세스는 더 많고, 더 깊이 있는 테스트를 받습니다.

---

## 3. 1페이지 테스트 계획 예시

당신이 직접 테스트 계획을 작성할 때, 이것을 기본 틀로 사용하세요.

```text
제목: [컴포넌트/앱]을 위한 테스트 계획
날짜:
작성자:

1. 범위(Scope):
   - 무엇을 테스트하는가?
   - 무엇을 테스트하지 않는가?

2. 주요 위험 요소:
   - R1: [위험 요소 + 이유]
   - R2: [위험 요소 + 이유]

3. 접근 방식:
   - 스모크 테스트
   - 테스트 케이스
   - 탐색적 테스트

4. 테스트 환경:
   - URL, 데이터, 계정

5. 시작 기준(Entry criteria):
   - 빌드가 작동함
   - 테스트 데이터가 준비됨

6. 종료 기준(Exit criteria):
   - 열려있는 P1/P0 버그가 없음
   - 스모크 테스트를 통과함

7. 역할:
   - 테스터
   - 코치 / 프로덕트 오너
```

## 4. 실습 과제: 나만의 미니 테스트 계획 만들기

이제 당신은 처음으로, 데모 앱의 작은 부분을 위한 테스트 계획을 직접 작성해 볼 것입니다.

### 과제

1. 데모 앱의 한 부분을 선택하세요. 예를 들어, 회원가입 기능.
2. 발생 확률 × 영향력을 사용해 3가지 위험 요소를 파악하세요.
3. 무엇을 테스트할 것인지 설명하세요 (*범위*).
4. 접근 방식을 선택하세요:
   - 스모크 테스팅
   - 테스트 케이스
   - 탐색적 테스트
5. 1페이지 테스트 계획 템플릿을 전부 작성하세요.

> **팁:**
> 짧고, 명확하고, 실용적으로 작성하세요.
> 테스트 계획은 보고서가 아닙니다 — 그것은 당신의 나침반입니다.

## 5. 성찰

당신의 테스트 계획에 대해 생각해 보세요:

- 어떤 위험 요소가 가장 중요했나요?
- 무엇을 범위 *밖*에 두었고, 그 이유는 무엇인가요?
- 세부 사항을 더 추가하고 싶나요, 아니면 줄이고 싶나요?

다음을 생각해 보세요:

- 어떤 선택이 의도적이었는지
- 어떤 부분이 추가적인 관심을 받았는지
- 그리고 더 큰 애플리케이션이었다면 당신의 접근 방식이 어떻게 달라졌을지
