# Module 9 – Final Project

This is the moment where all the knowledge from TestGarden comes together.

You're going to run a complete testing trajectory the way professional testers do:

- from test plan to bug reports
- from exploratory testing to API checks
- from risk analysis to presentation

You work:
- individually
- or in a small team

depending on your teacher's instructions.

---

## 1. Goal of the final project

The final project shows that you can:

- work in a structured way
- recognize risks
- design test cases
- master exploratory testing
- write clear bug reports
- test APIs
- present findings professionally

And perhaps even more important:

> that you're learning to look critically at quality, behavior, and user experience.

---

## 2. The project assignment

You're going to test a demo application provided by your teacher.

This could, for example, be:

- a webshop
- a registration form
- a mini API
- a dashboard
- or a combination of these

---

## 3. The complete test file

You'll ultimately deliver a complete test file.

### Checklist

- [ ] A 1-page test plan
- [ ] 8–12 test cases with techniques
- [ ] A completed smoke test
- [ ] An exploratory session report
- [ ] At least 5 bug reports
- [ ] 4–6 API checks
- [ ] (Optional) an automated test
- [ ] A short presentation

---

## 4. Deliverables

### 1) Test plan

Use the template from Module 3.

Make sure it's clear:
- what you're testing
- which risks matter
- what falls outside the scope

---

### 2) Test cases

Deliver 8–12 test cases.

Use at least:
- Equivalence Partitioning
- Boundary Value Analysis
- Decision Tables or State Transitions

---

### 3) Smoke Test

Run your own smoke test.

Note down:
- Pass/Fail
- GO/NO-GO
- notable risks

---

### 4) Exploratory Session

Run an exploratory session of around 60 minutes.

Create:
- notes
- observations
- findings
- conclusions

---

### 5) Bug reports

Write at least 5 professional bug reports.

Use:
- clear steps
- expected vs actual result
- severity / priority
- screenshots where possible

---

### 6) API checks

Run 4–6 API tests.

Describe:
- endpoint
- input
- status code
- response
- findings

---

### 7) (Optional) automation

For example, build:
- a login test
- a smoke test
- a simple Playwright flow

---

### 8) Presentation

Give a short presentation of 5–10 minutes.

Talk about:
- your approach
- the biggest risks
- the most important bugs
- what you learned

---

## 5. Modern quality: more than just bugs

Software quality nowadays isn't just about:

> "does it work technically?"

But also about:

- reliability
- security
- accessibility
- user experience
- performance
- AI behavior
- transparency

So also think about:

- How does the application feel for users?
- What risks arise from automation?
- What happens with unexpected behavior?
- What impact do errors have on people?

---

## 6. Collaborating as a tester

Professional testing is almost never solo work.

You collaborate with:
- developers
- product owners
- users
- designers
- AI tools
- other testers

That's why communication and collaboration matter just as much as technique.

---

## 7. Tips for success

### Organize your time
Work in small blocks.

### Think critically
Why is something a bug?
What's the impact?

### Combine techniques
Use:
- scripted testing
- exploratory testing
- API testing
- automation

### Let others look along
Other testers often find new insights.

### Collect evidence
Screenshots, logs, and examples help enormously.

---

## 8. Reflection

Look back at your learning process:

- Which technique did you use most?
- Which skill do you want to develop further?
- What did you learn about quality?
- Which bug did you find the most interesting?
- How do you see the role of testers in the future?

> Perhaps testing, in the end, isn't just about finding bugs,
>
> but about helping to build reliable, understandable, and human systems.
