# 모듈 9 – 최종 프로젝트

이것은 TestGarden에서 배운 모든 지식이 하나로 모이는 순간입니다.

당신은 전문 테스터들이 하는 것처럼 완전한 테스트 과정을 진행하게 됩니다:

- 테스트 계획부터 버그 리포트까지
- 탐색적 테스트부터 API 점검까지
- 위험 분석부터 발표까지

당신은 다음과 같이 작업합니다:
- 개별적으로
- 또는 소규모 팀으로

선생님의 지시에 따라 진행됩니다.

---

## 1. 최종 프로젝트의 목표

최종 프로젝트는 당신이 다음을 할 수 있음을 보여줍니다:

- 체계적으로 작업하기
- 위험을 인식하기
- 테스트 케이스를 설계하기
- 탐색적 테스트에 능숙하기
- 명확한 버그 리포트를 작성하기
- API를 테스트하기
- 발견 사항을 전문적으로 발표하기

그리고 어쩌면 더 중요한 것은:

> 품질, 행동, 그리고 사용자 경험을 비판적으로 바라보는 법을 배우고 있다는 것입니다.

---

## 2. 프로젝트 과제

당신은 선생님이 제공하는 데모 애플리케이션을 테스트하게 됩니다.

예를 들면 다음과 같은 것일 수 있습니다:

- 온라인 쇼핑몰
- 등록 양식
- 미니 API
- 대시보드
- 또는 이들의 조합

---

## 3. 완전한 테스트 문서 모음

최종적으로, 당신은 완전한 테스트 문서 모음을 제출합니다.

### 체크리스트

- [ ] 1페이지 테스트 계획
- [ ] 기법이 명시된 8~12개의 테스트 케이스
- [ ] 완료된 스모크 테스트
- [ ] 탐색적 세션 리포트
- [ ] 최소 5개의 버그 리포트
- [ ] 4~6개의 API 점검
- [ ] (선택 사항) 자동화된 테스트
- [ ] 짧은 발표

---

## 4. 산출물(Deliverables)

### 1) 테스트 계획

모듈 3의 템플릿을 사용하세요.

다음이 명확한지 확인하세요:
- 무엇을 테스트하는지
- 어떤 위험이 중요한지
- 무엇이 범위 밖에 있는지

---

### 2) 테스트 케이스

8~12개의 테스트 케이스를 제출하세요.

최소한 다음을 사용하세요:
- 동등 분할(Equivalence Partitioning)
- 경계값 분석(Boundary Value Analysis)
- 결정 테이블(Decision Tables) 또는 상태 전이 테스트(State Transitions)

---

### 3) 스모크 테스트

직접 스모크 테스트를 실행하세요.

기록할 내용:
- 통과/실패(Pass/Fail)
- GO/NO-GO
- 눈에 띄는 위험 요소

---

### 4) 탐색적 세션

약 60분간의 탐색적 세션을 진행하세요.

작성할 내용:
- 메모
- 관찰 사항
- 발견 사항
- 결론

---

### 5) 버그 리포트

최소 5개의 전문적인 버그 리포트를 작성하세요.

포함할 내용:
- 명확한 단계
- 예상 결과 vs 실제 결과
- 심각도(severity) / 우선순위(priority)
- 가능하다면 스크린샷

---

### 6) API 점검

4~6개의 API 테스트를 실행하세요.

기술할 내용:
- 엔드포인트
- 입력
- 상태 코드
- 응답
- 발견 사항

---

### 7) (선택 사항) 자동화

예를 들어, 다음을 만들어 보세요:
- 로그인 테스트
- 스모크 테스트
- 간단한 Playwright 플로우

---

### 8) 발표

5~10분 정도의 짧은 발표를 진행하세요.

이야기할 내용:
- 당신의 접근 방식
- 가장 큰 위험 요소
- 가장 중요한 버그
- 당신이 배운 것

---

## 5. 현대적 품질: 버그를 넘어서

오늘날 소프트웨어 품질은 더 이상 다음만을 의미하지 않습니다:

> "기술적으로 작동하는가?"

다음도 포함됩니다:

- 신뢰성
- 보안
- 접근성(accessibility)
- 사용자 경험
- 성능
- AI의 행동
- 투명성

그러므로 다음에 대해서도 생각해 보세요:

- 사용자에게 이 애플리케이션은 어떤 느낌을 주는가?
- 자동화로 인해 어떤 위험이 생기는가?
- 예상치 못한 행동이 발생하면 무슨 일이 일어나는가?
- 오류는 사람들에게 어떤 영향을 미치는가?

---

## 6. 테스터로서 협업하기

전문적인 테스팅은 거의 결코 혼자 하는 일이 아닙니다.

당신은 다음과 협업합니다:
- 개발자
- 프로덕트 오너
- 사용자
- 디자이너
- AI 도구
- 다른 테스터들

그래서 의사소통과 협업은 기술만큼이나 중요합니다.

---

## 7. 성공을 위한 팁

### 시간을 정리하세요
작은 블록 단위로 작업하세요.

### 비판적으로 생각하세요
왜 이것이 버그인가?
그 영향력은 무엇인가?

### 여러 기법을 결합하세요
다음을 사용하세요:
- 스크립트 기반 테스트
- 탐색적 테스트
- API 테스트
- 자동화

### 다른 사람들이 함께 살펴보게 하세요
다른 테스터들은 종종 새로운 통찰을 찾아냅니다.

### 증거를 모으세요
스크린샷, 로그, 예시는 큰 도움이 됩니다.

---

## 8. 성찰

당신의 학습 과정을 되돌아보세요:

- 어떤 기법을 가장 많이 사용했나요?
- 어떤 능력을 더 발전시키고 싶나요?
- 품질에 대해 무엇을 배웠나요?
- 어떤 버그가 가장 흥미로웠나요?
- 미래의 테스터 역할을 당신은 어떻게 보나요?

> 어쩌면 테스팅이란 결국 단순히 버그를 찾는 것이 아니라,
>
> 신뢰할 수 있고, 이해 가능하며, 인간적인 시스템을 만드는 것을 돕는 일인지도 모릅니다.
