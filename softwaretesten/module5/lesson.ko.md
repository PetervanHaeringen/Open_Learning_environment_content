# 모듈 5 – 탐색적 테스트(Exploratory Testing)

탐색적 테스트는 가장 강력하면서도 가장 재미있는 테스트 방식 중 하나입니다.

당신은 진짜 사용자가 그러하듯, 소프트웨어를 탐험하며 여행을 떠납니다:
호기심을 가지고, 창의적으로, 그리고 미리 정해진 단계 없이.

바로 이 지점에서 테스터는 진정한 가치를 더합니다.

---

## 1. 탐색적 테스트란 무엇인가?

탐색적 테스트란 **발견하며** 테스트하는 것을 의미합니다:

당신은 동시에:
- 무엇을 테스트하고 싶은지 생각하고
- 그것을 실행하며
- 테스트하는 동안 배웁니다

이것은 딱딱한 스크립트와는 정반대입니다.

> 당신은 자신의 눈과 직감, 그리고 소프트웨어가 보내는 신호를 따라갑니다.

### 특징

- 사용자처럼 생각한다
- 클릭하고, 시도하고, 실험한다
- 이상한 결함이나 예상치 못한 상황을 따라간다
- 정해진 단계 목록 없이 조사한다

---

## 2. 왜 탐색적 테스트가 중요한가?

탐색적 테스트는 어떤 문서나 테스트 케이스에도 결코 나타나지 않는 버그를 종종 찾아냅니다.

### 탐색을 통해서만 종종 발견되는 문제들

- 빠르게 클릭할 때 나타나는 이상한 동작
- 데스크톱과 다른 모바일에서의 동작
- 비논리적인 흐름
- 혼란스러운 화면 전환
- 작은 레이아웃이나 텍스트 문제

그래서 탐색적 테스트는 스크립트 기반 테스트를 완벽하게 보완해줍니다.

---

## 3. 세션 기반 테스트 관리(Session-Based Test Management, SBTM)

탐색적 테스트를 하는 동안, 당신은 종종 짧은 세션 단위로 작업합니다.

이러한 세션은 보통 세 가지 요소로 이루어집니다:

- **차터(Charter)** — 무엇을 조사할 것인가?
- **타이머(Timer)** — 보통 30분에서 60분
- **메모하기** — 무엇을 보았고, 무엇이 눈에 띄었는가?

### 차터(Charter) 예시

> 등록 페이지에서 비논리적인 흐름, 오류 메시지, 모바일 사용 경험을 조사한다.

---

## 4. 탐색적 테스트는 어떻게 하는가?

몇 가지 실용적인 팁:

- 명확한 목표로 시작하세요
- 사용자처럼 생각하세요
- 질문을 던지세요:
  - "만약 …라면 무슨 일이 일어날까?"
- 예상치 못한 상황을 따라가세요
- 눈에 띄는 것은 무엇이든 메모하세요
- 빠르게도, 천천히도 테스트하세요
- 모바일, 태블릿, 다른 브라우저에서도 테스트하세요

> 탐색적 테스트는 혼돈이 아닙니다.
> 당신은 목적을 가지고 일하되, 발견을 위한 여지를 남겨둡니다.

---

## 5. 세션 리포트(Session Report)

세션 중이나 이후에 짧은 리포트를 작성하세요.

```text
세션 리포트 – [대상 컴포넌트] – [날짜]

차터(Charter):
  당신의 목표는 무엇이었나요?

소요 시간:
  얼마나 오래 테스트했나요?

관찰 내용:
  - 무엇을 보았나요?
  - 어떤 이상한 상황이 나타났나요?

발견된 이슈:
  - 버그 1: 설명 + 재현 가능한가?
  - 버그 2: 설명 + 재현 가능한가?
  - 버그 3: 설명 + 재현 가능한가?

메모:
  질문, 아이디어, 의문점
```

---

## 6. 실습 과제: 60분 탐색적 테스트 세션

이제 당신 스스로 탐색적 테스트 세션을 진행합니다.

### 과제

1. 대상을 하나 선택하세요:
   - 회원가입
   - 로그인
   - 장바구니
   - 또는 다른 대상

2. 한 문장짜리 차터(charter)를 작성하세요.

3. 타이머를 60분으로 설정하세요.

4. 탐색적으로 테스트하며, 눈에 띄는 모든 것을 메모하세요.

5. 세션 리포트를 작성하세요.

6. 최소 3개의 버그를 각각 별도의 버그 리포트로 제출하세요.

> 정기적으로 스스로에게 물어보세요:
> "사용자는 어디에서 혼란스러워할까?"

---

## 7. 성찰

당신의 세션을 돌아보세요:

- 무엇이 당신을 놀라게 했나요?
- 테스트 케이스만으로는 결코 찾지 못했을 버그는 무엇인가요?
- 어떤 능력이 유용했나요?
- 다음번에는 무엇을 다르게 하시겠습니까?
