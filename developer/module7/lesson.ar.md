# الوحدة 7 — ارتكاب الأخطاء وقراءتها

كل برنامج تكتبه سيخطئ في مرحلة ما.
هذا ليس أمرًا خطيرًا — إنه أمر لا مفر منه. السؤال ليس *هل* سترتكب أخطاء، بل ما مدى سرعتك في إيجادها وإصلاحها.

المطوّرون الجيدون ليسوا أشخاصًا لا يرتكبون أخطاءً. إنهم أشخاص يقرؤون الأخطاء بسرعة.

---

## 1. ثلاثة أنواع من الأخطاء

**خطأ نحوي (SyntaxError)**
الكود غير صحيح نحويًا — اللغة لا تفهمه.

```javascript
console.log("مرحبا"   // نسي قوس الإغلاق
```
```
Uncaught SyntaxError: Unexpected end of input
```

لا يستطيع المفسّر (interpreter) حتى بدء تشغيل الكود. ابحث عن أقواس أو علامات اقتباس أو أقواس معقوفة ناقصة.

---

**خطأ في وقت التشغيل (Runtime error)**
الكود صحيح نحويًا، لكنه يفشل أثناء التنفيذ.

```javascript
let رقم = null;
console.log(رقم.toString());
```
```
Uncaught TypeError: Cannot read properties of null
```

يبدو الكود صالحًا لكنه يحاول فعل شيء غير ممكن — في هذه الحالة، استدعاء دالة (method) على `null`.

---

**خطأ منطقي (Logic error)**
يعمل الكود دون أي رسالة خطأ، لكنه لا يفعل ما كنت تقصده.

```javascript
function المتوسط(a, b) {
    return a + b / 2;   // خطأ: يقسّم فقط b على 2
}

console.log(المتوسط(4, 6));  // يعطي 7، وليس 5
```

هذا هو أصعب نوع من الأخطاء — الحاسوب لا يشتكي. عليك أن تكتشف بنفسك أين الخطأ.

---

## 2. قراءة رسائل الأخطاء

رسالة الخطأ ليست هجومًا. إنها معلومة.

```
Uncaught TypeError: الأسماء.push is not a function
    at <anonymous>:3:7
```

اقرأها على ثلاث خطوات:

1. **نوع الخطأ** — `TypeError`: شيء ما لديه النوع الخاطئ
2. **الوصف** — `الأسماء.push is not a function`: المتغيّر `الأسماء` لا يملك دالة (method) اسمها `push`
3. **الموقع** — `at <anonymous>:3:7`: السطر 3، الحرف 7

ابدأ دائمًا برسالة الخطأ الأولى. أحيانًا يتسبب خطأ واحد في سلسلة من الرسائل الأخرى.

---

## 3. تصحيح الأخطاء (Debugging) كعملية تفكير

تصحيح الأخطاء هو تفكير علمي: وضع فرضية، اختبارها، ثم استخلاص نتيجة.

**الخطوة 1 — أعِد إنتاج المشكلة**
هل يمكنك إحداث المشكلة بشكل موثوق؟ إذا لم تكن تعرف متى تحدث، فلن تتمكن من إصلاحها.

**الخطوة 2 — اعزل المشكلة**
قلّص الكود حتى تصل إلى أصغر نسخة لا تزال تفشل. كلما قلّ الكود، كان أسهل للفهم.

**الخطوة 3 — ضع فرضية**
"أعتقد أن الخطأ يحدث لأن المتغيّر x فارغ في هذه النقطة."

**الخطوة 4 — اختبر الفرضية**
أضف `console.log` لترى ما هي القيم:

```javascript
function احسبالخصم(السعر, النسبة) {
    console.log("السعر:", السعر);           // تحقق من المدخل
    console.log("النسبة:", النسبة);  // تحقق من المدخل
    let الخصم = السعر * النسبة / 100;
    console.log("الخصم:", الخصم);        // تحقق من الحساب
    return السعر - الخصم;
}
```

**الخطوة 5 — عدّل واختبر مجددًا**
هل كانت فرضيتك صحيحة؟ إذا لم تكن كذلك، ضع فرضية جديدة.

---

## 4. الأخطاء الشائعة وكيفية إصلاحها

| الخطأ | السبب | الحل |
|------|---------|-----------|
| `is not defined` | المتغيّر غير موجود أو الاسم مكتوب خطأ | تحقق من الاسم وما إذا استُخدم `let` |
| `is not a function` | استدعاء شيء ليس دالة | تحقق من نوع المتغيّر |
| `Cannot read properties of null` | استدعاء دالة على null/undefined | تحقق مما إذا كان المتغيّر يحمل قيمة |
| `SyntaxError` | قوس أو علامة اقتباس أو قوس معقوف ناقص | عُدّ الأقواس — هل هي مُغلقة؟ |
| حلقة لا نهائية | شرط التوقف لا يصبح خطأً أبدًا | تحقق مما إذا كان المتغيّر في الشرط يتغيّر |

---

## 5. إصلاح البرامج المعطّلة

فيما يلي ثلاث قطع من كود معطّل. ابحث عن الخطأ وأصلحه.

**البرنامج المعطّل 1:**
```javascript
function رحّب(الاسم) {
    console.log("مرحبًا، " + الاسم)
}

رحّب("Ali"
```

**البرنامج المعطّل 2:**
```javascript
let الدرجة = "95";

if (الدرجة >= 90) {
    console.log("ناجح");
}
```
*(تلميح: `الدرجة` هي نص (string)، وليست رقمًا. ماذا يفعل `>=` مع نص؟)*

**البرنامج المعطّل 3:**
```javascript
function اضرب(a, b) {
    return a + b;
}

console.log(اضرب(3, 4));  // متوقَّع 12، لكن يعطي 7
```

---

## 6. عقلية مصحّح الأخطاء

أفضل المطوّرين لا يستاؤون من الأخطاء — بل يشعرون بالفضول.

الخطأ يعني: *الحاسوب يخبرك بشيء عن الكود الخاص بك لم تكن تعرفه من قبل.*

هذا أمر ثمين. كل خطأ تُصلحه يجعلك أفضل في تجنّب نفس الخطأ في المرة القادمة.

> "تصحيح الأخطاء أشبه بأن تكون المحقق في قصة بوليسية، وأنت في الوقت ذاته المجرم أيضًا."
