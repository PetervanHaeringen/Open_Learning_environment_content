# 모듈 7 — 오류를 만들고, 읽어내기

당신이 작성하는 모든 프로그램은 언젠가 반드시 잘못될 것입니다.
그것은 큰일이 아닙니다 — 피할 수 없는 일이니까요. 중요한 것은 당신이 실수를 *하느냐 마느냐*가 아니라, 그것을 얼마나 빨리 찾아내고 고치느냐입니다.

훌륭한 개발자란 실수를 하지 않는 사람이 아닙니다. 오류를 빠르게 읽어내는 사람입니다.

---

## 1. 세 가지 종류의 오류

**구문 오류 (SyntaxError)**
코드가 문법적으로 잘못되어 있습니다 — 언어가 그것을 이해하지 못합니다.

```javascript
console.log("안녕하세요"   // 닫는 괄호를 빠뜨림
```
```
Uncaught SyntaxError: Unexpected end of input
```

인터프리터는 코드 실행조차 시작할 수 없습니다. 괄호, 따옴표, 중괄호가 빠지지 않았는지 찾아보세요.

---

**런타임 오류 (Runtime error)**
코드는 문법적으로는 옳지만, 실행 중에 문제가 발생합니다.

```javascript
let 숫자 = null;
console.log(숫자.toString());
```
```
Uncaught TypeError: Cannot read properties of null
```

코드는 유효해 보이지만, 불가능한 일을 시도하고 있습니다 — 이 경우에는, `null`에 대해 메서드를 호출하려 하고 있습니다.

---

**논리 오류 (Logic error)**
코드는 아무런 오류 메시지 없이 실행되지만, 당신이 의도한 대로 동작하지 않습니다.

```javascript
function 평균(a, b) {
    return a + b / 2;   // 버그: b만 2로 나누고 있음
}

console.log(평균(4, 6));  // 5가 아니라 7이 나옴
```

이것이 가장 까다로운 종류의 오류입니다 — 컴퓨터는 불평하지 않습니다. 무엇이 잘못되었는지는 당신 스스로 찾아내야 합니다.

---

## 2. 오류 메시지 읽기

오류 메시지는 공격이 아닙니다. 그것은 정보입니다.

```
Uncaught TypeError: 이름들.push is not a function
    at <anonymous>:3:7
```

세 단계로 읽어보세요:

1. **오류 종류** — `TypeError`: 무언가의 타입이 잘못됨
2. **설명** — `이름들.push is not a function`: 변수 `이름들`에는 `push`라는 메서드가 없음
3. **위치** — `at <anonymous>:3:7`: 3번째 줄, 7번째 문자

항상 첫 번째 오류 메시지부터 시작하세요. 때로는 하나의 오류가 다른 여러 메시지들의 연쇄를 일으키기도 합니다.

---

## 3. 사고 과정으로서의 디버깅

디버깅은 과학적 사고입니다: 가설을 세우고, 검증하고, 결론을 내리는 것입니다.

**1단계 — 문제를 재현하라**
그 문제를 안정적으로 다시 발생시킬 수 있나요? 언제 잘못되는지 모른다면, 고칠 수도 없습니다.

**2단계 — 문제를 격리하라**
여전히 오류가 발생하는 가장 작은 버전이 될 때까지 코드를 줄여나가세요. 코드가 적을수록 이해하기 쉽습니다.

**3단계 — 가설을 세워라**
"이 시점에서 변수 x가 비어 있어서 잘못되는 것 같다."

**4단계 — 가설을 검증하라**
`console.log`를 추가해서 실제 값이 무엇인지 확인해 보세요:

```javascript
function 할인계산(가격, 비율) {
    console.log("가격:", 가격);           // 입력값 확인
    console.log("비율:", 비율);  // 입력값 확인
    let 할인액 = 가격 * 비율 / 100;
    console.log("할인액:", 할인액);        // 계산 확인
    return 가격 - 할인액;
}
```

**5단계 — 수정하고 다시 검증하라**
당신의 가설이 맞았나요? 그렇지 않다면, 새로운 가설을 세우세요.

---

## 4. 흔한 실수와 그 해결 방법

| 오류 | 원인 | 해결 방법 |
|------|---------|-----------|
| `is not defined` | 변수가 존재하지 않거나 이름 철자가 틀림 | 이름을 확인하고 `let`을 사용했는지 확인 |
| `is not a function` | 함수가 아닌 것을 호출함 | 변수의 타입을 확인 |
| `Cannot read properties of null` | null/undefined에서 메서드를 호출함 | 변수가 값을 가지고 있는지 확인 |
| `SyntaxError` | 괄호, 따옴표, 중괄호가 빠짐 | 괄호를 세어보세요 — 다 닫혀 있나요? |
| 무한 루프 | 정지 조건이 절대 거짓이 되지 않음 | 조건에 있는 변수가 실제로 변하는지 확인 |

## 5. 고장난 프로그램 고치기

아래에 고장난 코드 세 개가 있습니다. 버그를 찾아 고쳐보세요.

**고장난 프로그램 1:**
```javascript
function 인사하기(이름) {
    console.log("안녕하세요, " + 이름)
}

인사하기("Ali"
```

**고장난 프로그램 2:**
```javascript
let 점수 = "95";

if (점수 >= 90) {
    console.log("합격");
}
```
*(힌트: `점수`는 문자열이지, 숫자가 아닙니다. `>=`는 문자열에 대해 어떻게 동작할까요?)*

**고장난 프로그램 3:**
```javascript
function 곱하기(a, b) {
    return a + b;
}

console.log(곱하기(3, 4));  // 12를 기대했지만 7이 나옴
```

## 6. 디버거의 마음가짐

최고의 개발자들은 오류에 짜증을 내지 않습니다 — 그들은 호기심을 느낍니다.

오류가 의미하는 것은 이것입니다: *컴퓨터가 당신 자신의 코드에 대해, 당신이 아직 몰랐던 무언가를 알려주고 있다는 것.*

그것은 가치 있는 일입니다. 당신이 고친 버그 하나하나가, 다음번에 같은 실수를 피하는 데 더 능숙해지도록 만들어줍니다.

> "디버깅이란, 탐정 소설 속에서 당신이 탐정인 동시에 범인이기도 한 것과 같다."
