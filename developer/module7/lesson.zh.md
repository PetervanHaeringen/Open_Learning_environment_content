# 模块7 — 犯错与读懂错误

你写的每一个程序，总有一天会出问题。
这没什么大不了——这是不可避免的。问题不在于你*是否*会犯错，而在于你能多快发现并解决它。

优秀的开发者，并不是从不犯错的人。而是能够迅速读懂错误信息的人。

---

## 1. 三种类型的错误

**语法错误（SyntaxError）**
代码在语法上是错误的——这门语言根本读不懂它。

```javascript
console.log("你好"   // 忘记加右括号了
```
```
Uncaught SyntaxError: Unexpected end of input
```

解释器甚至都无法开始运行这段代码。要检查是否缺少括号、引号或花括号。

---

**运行时错误（Runtime error）**
代码在语法上是正确的，但在执行过程中出了问题。

```javascript
let 数字 = null;
console.log(数字.toString());
```
```
Uncaught TypeError: Cannot read properties of null
```

代码看起来是有效的，但它试图做一件不可能的事情——在这个例子里，是在`null`上调用了一个方法。

---

**逻辑错误（Logic error）**
代码运行时不会报错，但结果并不是你想要的。

```javascript
function 平均值(a, b) {
    return a + b / 2;   // 错误：只把b除以了2
}

console.log(平均值(4, 6));  // 得到7，而不是5
```

这是最棘手的一类错误——计算机不会抱怨。你必须自己找出问题出在哪里。

---

## 2. 读懂错误信息

一条错误信息，不是在攻击你。它是一种信息。

```
Uncaught TypeError: 名字们.push is not a function
    at <anonymous>:3:7
```

按三步来读：

1. **错误类型**——`TypeError`：某个东西的类型不对
2. **描述**——`名字们.push is not a function`：变量`名字们`没有`push`这个方法
3. **位置**——`at <anonymous>:3:7`：第3行，第7个字符

永远先从第一条错误信息开始看。有时候，一个错误会引发一连串其他的错误提示。

---

## 3. 把调试当作一种思考过程

调试（debugging）就是科学思维：提出假设、进行测试、得出结论。

**第一步——重现问题**
你能可靠地让这个问题再次出现吗？如果你不知道它什么时候会出错，你就无法修复它。

**第二步——隔离问题**
不断缩小代码范围，直到得到那个仍然会出错的、最精简的版本。代码越少，就越容易理解。

**第三步——提出假设**
"我认为，出错的原因是，此时变量x是空的。"

**第四步——验证假设**
加入`console.log`，看看具体的值是什么：

```javascript
function 计算折扣(价格, 百分比) {
    console.log("价格:", 价格);           // 检查输入
    console.log("百分比:", 百分比);  // 检查输入
    let 折扣 = 价格 * 百分比 / 100;
    console.log("折扣:", 折扣);        // 检查计算过程
    return 价格 - 折扣;
}
```

**第五步——调整后再次测试**
你的假设对不对？如果不对，就提出一个新的假设。

## 4. 常见错误及其解决方法

| 错误 | 原因 | 解决方法 |
|------|---------|-----------|
| `is not defined` | 变量不存在，或名字拼错了 | 检查名字，并确认是否使用了`let` |
| `is not a function` | 调用了一个并非函数的东西 | 检查该变量的类型 |
| `Cannot read properties of null` | 在null/undefined上调用了方法 | 检查该变量是否真的有值 |
| `SyntaxError` | 缺少括号、引号或花括号 | 数一数括号——都闭合了吗？ |
| 无限循环 | 停止条件永远不会变为假 | 检查条件里的变量是否真的在变化 |

## 5. 修复出错的程序

下面是三段有问题的代码。找出错误，并修复它们。

**出错的程序1：**
```javascript
function 问候(姓名) {
    console.log("你好，" + 姓名)
}

问候("Ali"
```

**出错的程序2：**
```javascript
let 分数 = "95";

if (分数 >= 90) {
    console.log("及格了");
}
```
*（提示：`分数`是一个字符串，而不是数字。`>=`用在字符串上会发生什么？）*

**出错的程序3：**
```javascript
function 相乘(a, b) {
    return a + b;
}

console.log(相乘(3, 4));  // 期望得到12，实际得到7
```

## 6. 调试者应有的心态

最优秀的开发者，遇到错误时不会烦躁——他们会感到好奇。

一个错误，意味着：*计算机正在告诉你一些关于你自己代码的、你此前还不知道的事情。*

这非常有价值。你修复的每一个bug，都会让你下一次更擅长避免同样的错误。

> "调试，就像在一个侦探故事里，你既是那个侦探，同时又是那个凶手。"
