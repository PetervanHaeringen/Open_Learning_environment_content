# モジュール7 — エラーを起こし、そして読み解く

あなたが書くどんなプログラムも、いつかは必ず間違いを起こします。
それは大したことではありません——避けられないことだからです。問題は、あなたが間違いを*犯すかどうか*ではなく、どれだけ早くそれを見つけて直せるか、です。

優れた開発者とは、間違いをしない人のことではありません。エラーを素早く読み解ける人のことです。

---

## 1. 3種類のエラー

**構文エラー（SyntaxError）**
コードが文法的に間違っている——言語がそれを理解できません。

```javascript
console.log("こんにちは"   // 閉じ括弧を忘れている
```
```
Uncaught SyntaxError: Unexpected end of input
```

インタープリタは、コードの実行を開始することすらできません。括弧、引用符、波括弧が足りていないかを確認しましょう。

---

**実行時エラー（Runtime error）**
コードは文法的には正しいのに、実行中に問題が起こります。

```javascript
let 数値 = null;
console.log(数値.toString());
```
```
Uncaught TypeError: Cannot read properties of null
```

コードは一見有効に見えますが、不可能なことをしようとしています——この場合は、`null`に対してメソッドを呼び出そうとしています。

---

**ロジックエラー（Logic error）**
コードはエラーメッセージなしで実行されますが、意図した通りには動きません。

```javascript
function 平均(a, b) {
    return a + b / 2;   // バグ：bだけを2で割ってしまっている
}

console.log(平均(4, 6));  // 5ではなく、7になってしまう
```

これは最も厄介なタイプのエラーです——コンピューターは文句を言いません。何が間違っているのか、自分自身で見つけ出さなければなりません。

---

## 2. エラーメッセージを読む

エラーメッセージは、攻撃ではありません。それは情報です。

```
Uncaught TypeError: 名前一覧.push is not a function
    at <anonymous>:3:7
```

これを、3つのステップで読み解きます：

1. **エラーの種類**——`TypeError`：何かの型（type）が間違っている
2. **説明**——`名前一覧.push is not a function`：変数`名前一覧`には`push`というメソッドが存在しない
3. **場所**——`at <anonymous>:3:7`：3行目、7文字目

常に、最初のエラーメッセージから始めましょう。時には、ひとつのエラーが、他の多くのエラーメッセージを連鎖的に引き起こすことがあります。

---

## 3. 思考プロセスとしてのデバッグ

デバッグとは、科学的な思考のプロセスです：仮説を立て、検証し、結論を導く。

**ステップ1——問題を再現する**
その問題を、確実に発生させることができますか？いつ問題が起きるのかわからなければ、修正することはできません。

**ステップ2——問題を切り分ける**
まだ問題が起きる、最小限のコードになるまで削っていきます。コードが少ないほど、理解しやすくなります。

**ステップ3——仮説を立てる**
「この時点で、変数xが空になっているから、間違いが起きているのだと思う。」

**ステップ4——仮説を検証する**
`console.log`を追加して、実際の値を確認します：

```javascript
function 割引を計算する(価格, パーセント) {
    console.log("価格:", 価格);           // 入力を確認する
    console.log("パーセント:", パーセント);  // 入力を確認する
    let 割引額 = 価格 * パーセント / 100;
    console.log("割引額:", 割引額);        // 計算を確認する
    return 価格 - 割引額;
}
```

**ステップ5——修正して、もう一度検証する**
あなたの仮説は正しかったですか？もし違っていたら、新しい仮説を立てましょう。

---

## 4. よくある間違いと、その直し方

| エラー | 原因 | 解決策 |
|------|---------|-----------|
| `is not defined` | 変数が存在しない、または名前のスペルが間違っている | 名前と、`let`を使ったかどうかを確認する |
| `is not a function` | 関数ではないものを呼び出している | その変数の型（type）を確認する |
| `Cannot read properties of null` | null/undefinedに対してメソッドを呼び出している | その変数が値を持っているか確認する |
| `SyntaxError` | 括弧、引用符、波括弧が不足している | 括弧の数を数える——ちゃんと閉じられているか？ |
| 無限ループ | 停止条件が決してfalseにならない | 条件の中の変数が変化しているか確認する |

## 5. 壊れたプログラムを直す

以下に、壊れたコードが3つあります。バグを見つけて、修正してください。

**壊れたプログラム1：**
```javascript
function 挨拶(名前) {
    console.log("こんにちは、" + 名前)
}

挨拶("Ali"
```

**壊れたプログラム2：**
```javascript
let 点数 = "95";

if (点数 >= 90) {
    console.log("合格");
}
```
*（ヒント：`点数`は数値ではなく文字列（string）です。文字列に対して`>=`を使うと、どうなるでしょうか？）*

**壊れたプログラム3：**
```javascript
function 掛け算(a, b) {
    return a + b;
}

console.log(掛け算(3, 4));  // 期待される結果は12なのに、7になってしまう
```

## 6. デバッガーの心構え

最も優れた開発者たちは、エラーに苛立ったりしません——好奇心を持つのです。

エラーが意味しているのは：*コンピューターが、あなた自身のコードについて、あなたがまだ知らなかった何かを教えてくれている*、ということです。

それは、価値のあることです。ひとつバグを直すたびに、あなたは次に同じ間違いを避けることが、より上手くなっていきます。

> 「デバッグとは、探偵小説の中で、あなた自身が探偵であると同時に、犯人でもあるようなものだ。」
