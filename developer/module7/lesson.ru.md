# Модуль 7 — Делать и читать ошибки

Каждая программа, которую вы напишете, однажды сломается.
Это не страшно — это неизбежно. Вопрос не в том, *будете* ли вы совершать ошибки, а в том, насколько быстро вы их находите и исправляете.

Хорошие разработчики — это не те, кто не совершает ошибок. Это те, кто быстро читает ошибки.

---

## 1. Три типа ошибок

**Синтаксическая ошибка (SyntaxError)**
Код грамматически некорректен — язык его не понимает.

```javascript
console.log("Привет"   // забыта закрывающая скобка
```
```
Uncaught SyntaxError: Unexpected end of input
```

Интерпретатор даже не может начать выполнение кода. Ищите пропущенные скобки, кавычки или фигурные скобки.

---

**Ошибка выполнения (Runtime error)**
Код грамматически корректен, но что-то идёт не так во время выполнения.

```javascript
let число = null;
console.log(число.toString());
```
```
Uncaught TypeError: Cannot read properties of null
```

Код выглядит валидным, но пытается сделать что-то невозможное — в данном случае вызвать метод у `null`.

---

**Логическая ошибка**
Код выполняется без каких-либо сообщений об ошибке, но делает не то, что вы имели в виду.

```javascript
function среднее(a, b) {
    return a + b / 2;   // ошибка: делит на 2 только b
}

console.log(среднее(4, 6));  // выдаёт 7, а не 5
```

Это самый коварный тип ошибки — компьютер не жалуется. Вам нужно самостоятельно обнаружить, что не так.

---

## 2. Чтение сообщений об ошибках

Сообщение об ошибке — это не нападение. Это информация.

```
Uncaught TypeError: имена.push is not a function
    at <anonymous>:3:7
```

Читайте его в три шага:

1. **Тип ошибки** — `TypeError`: у чего-то неправильный тип
2. **Описание** — `имена.push is not a function`: у переменной `имена` нет метода `push`
3. **Расположение** — `at <anonymous>:3:7`: строка 3, символ 7

Всегда начинайте с первого сообщения об ошибке. Иногда одна ошибка вызывает целый каскад других сообщений.

## 3. Отладка как процесс мышления

Отладка (debugging) — это научное мышление: сформулировать гипотезу, проверить её, сделать вывод.

**Шаг 1 — Воспроизведите проблему**
Можете ли вы надёжно вызвать эту проблему? Если вы не знаете, когда возникает ошибка, вы не сможете её исправить.

**Шаг 2 — Изолируйте проблему**
Уменьшайте код, пока не получите самую маленькую версию, которая всё ещё ломается. Чем меньше кода, тем легче его понять.

**Шаг 3 — Сформулируйте гипотезу**
«Я думаю, ошибка возникает потому, что переменная x в этой точке пуста».

**Шаг 4 — Проверьте гипотезу**
Добавьте `console.log`, чтобы увидеть значения:

```javascript
function вычислитьСкидку(цена, процент) {
    console.log("цена:", цена);           // проверить вход
    console.log("процент:", процент);  // проверить вход
    let скидка = цена * процент / 100;
    console.log("скидка:", скидка);        // проверить вычисление
    return цена - скидка;
}
```

**Шаг 5 — Скорректируйте и проверьте снова**
Была ли ваша гипотеза верной? Если нет, сформулируйте новую.

## 4. Частые ошибки и способы их устранения

| Ошибка | Причина | Решение |
|------|---------|-----------|
| `is not defined` | Переменной не существует или имя написано с опечаткой | Проверьте имя и использовалось ли `let` |
| `is not a function` | Вызов чего-то, что не является функцией | Проверьте тип переменной |
| `Cannot read properties of null` | Вызов метода у null/undefined | Проверьте, есть ли у переменной значение |
| `SyntaxError` | Пропущена скобка, кавычка или фигурная скобка | Посчитайте скобки — все ли они закрыты? |
| Бесконечный цикл | Условие остановки никогда не становится ложным | Проверьте, меняется ли переменная в условии |

## 5. Исправление сломанных программ

Ниже приведены три фрагмента сломанного кода. Найдите ошибку и исправьте её.

**Сломанная программа 1:**
```javascript
function поприветствовать(имя) {
    console.log("Привет, " + имя)
}

поприветствовать("Ali"
```

**Сломанная программа 2:**
```javascript
let балл = "95";

if (балл >= 90) {
    console.log("Сдал");
}
```
*(Подсказка: `балл` — это строка, а не число. Что делает `>=` со строкой?)*

**Сломанная программа 3:**
```javascript
function умножить(a, b) {
    return a + b;
}

console.log(умножить(3, 4));  // ожидалось 12, получено 7
```

---

## 6. Образ мышления отладчика

Лучшие разработчики не раздражаются из-за ошибок — они становятся любопытными.

Ошибка означает: *компьютер сообщает вам что-то о вашем собственном коде, чего вы ещё не знали.*

Это ценно. Каждая исправленная ошибка делает вас лучше в предотвращении той же самой ошибки в следующий раз.

> «Отладка — это как быть детективом в детективной истории, где вы одновременно и убийца».
