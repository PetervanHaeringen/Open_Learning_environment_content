# 모듈 3 — 언어와 추상화

당신이 Python을 작성할 때, 사실 당신은 컴퓨터와 직접 대화하고 있는 것이 아닙니다.
당신은 Python과 대화합니다. Python은 C와 대화합니다. C는 어셈블리와 대화합니다. 어셈블리는 프로세서와 대화합니다.

각 층은 그 아래 층의 복잡함을 감춥니다. 이것을 **추상화(abstraction)**라고 부릅니다 — 그리고 이것은 컴퓨터 과학에서 가장 강력한 개념 중 하나입니다.

---

## 1. 컴퓨터는 오직 0과 1만을 이해한다

가장 근본적인 수준에서, 컴퓨터는 단 한 가지만을 이해합니다: 전류가 흐르는지, 흐르지 않는지. 켜져 있는지, 꺼져 있는지. 1인지, 0인지.

당신이 언젠가 작성하게 될 모든 코드는 결국 1과 0으로 이루어진 긴 나열로 변환됩니다 — 이것이 바로 **기계어(machine language)**입니다.

기계어로 표현한 간단한 덧셈은 이렇게 생겼습니다:
```
10110000 01100001
00000101 00000001
10100010 01100001
```

이것이 문자 그대로 프로세서가 실행하는 내용입니다. 인간은 이것을 실수 없이 쓰거나 읽을 수 없습니다. 그래서 다음 층이 발명된 것입니다.

---

## 2. 어셈블리 — 명령어에 이름 붙이기

1950년대에 프로그래머들은 이렇게 생각했습니다: 가장 자주 사용하는 명령어들에 이름을 붙이면 어떨까?

`10110000 01100001` 대신 다음과 같이 씁니다:
```asm
MOV AL, 1
ADD AL, 1
MOV 메모리, AL
```

`MOV`는 "값을 이동하라"는 뜻입니다. `ADD`는 "더하라"는 뜻입니다.
이것들은 0과 1로 이루어진 명령어와 완전히 동일한 것입니다 — 다만 인간이 읽을 수 있게 된 것뿐입니다.

**어셈블러(assembler)**는 어셈블리 코드를 기계어로 변환합니다.

어셈블리는 엄청난 진전이었습니다. 하지만 여전히 하드웨어와 매우 가까웠습니다 — 자신이 얼마나 많은 메모리를 가지고 있는지, 어떤 레지스터를 사용할 수 있는지, 프로세서가 어떻게 구성되어 있는지를 정확히 알아야 했습니다.

---

## 3. 고급 언어 — 인간을 위해 쓰기

1950~60년대에 새로운 아이디어가 등장했습니다: 인간의 언어와 더 비슷한 코드를 쓴다면 어떨까?

**FORTRAN**(1957년) — 과학 계산을 위해:
```fortran
X = A + B * C
```

**COBOL**(1959년) — 비즈니스 응용 프로그램을 위해:
```cobol
ADD SALARY TO TOTAL-WAGES
```

**C**(1972년) — 간결하고 강력하며, 하드웨어에 가깝지만 읽기 쉬운:
```c
int som = a + b;
```

**Python**(1991년) — 거의 영어처럼 읽힐 정도로 읽기 쉬운:
```python
som = a + b
```

세대를 거듭할수록 언어들은 더 읽기 쉬워졌습니다. 그리고 한 단계씩 나아갈 때마다, 더 많은 복잡함이 감춰졌습니다.

## 4. 컴파일러와 인터프리터 — 번역가들

읽기 쉬운 코드는 어떻게 프로세서에까지 도달할까요?

**컴파일러(compiler)** 또는 **인터프리터(interpreter)**를 통해서입니다.

**컴파일러** — 프로그램이 실행되기 전에, 전체 코드를 한 번에 기계어로 번역합니다.
장점: 프로그램이 빠릅니다.
단점: 변경할 때마다 다시 컴파일해야 합니다.
예시: C, C++, Rust.

**인터프리터** — 프로그램이 실행되는 동안, 코드를 한 줄씩 번역합니다.
장점: 변경 사항의 결과를 즉시 확인할 수 있습니다.
단점: 조금 더 느립니다.
예시: Python, JavaScript, Ruby.

개발자로서 접하게 될 대부분의 언어는 인터프리터 방식입니다 — Python과 JavaScript 둘 다 그렇습니다. 이것은 학습에 유리합니다: 한 줄을 쓰면, 무슨 일이 일어나는지 바로 확인할 수 있으니까요.

## 5. 왜 추상화는 이렇게 강력한가?

상상해 보세요. 웹사이트를 만들 때마다, 화면에 텍스트 하나를 표시하기 위해 매번 완전한 기계어 코드를 처음부터 작성해야 한다면 어떨까요? "Hello world" 이상은 결코 나아가지 못할 것입니다.

추상화 덕분에 우리는 **다른 사람들이 이미 만들어놓은 것 위에 쌓아 올릴 수** 있게 됩니다.

Python은 C로 작성되었습니다.
C는 어셈블리로 작성되었습니다.
어셈블리는 기계어로 작성되었습니다.
기계어는 트랜지스터에 의해 실행됩니다.
트랜지스터는 전기공학자들이 설계합니다.

유용한 무언가를 하는 프로그램을 작성하기 위해, 당신은 이 모든 것을 알 필요가 없습니다. 당신은 다른 사람들이 이미 만들어놓은 층들을 그저 사용할 뿐입니다.

이것은 또한 오픈소스의 철학이기도 합니다: 다음 사람이 그 위에 더 쌓아 올릴 수 있도록, 코드를 공유하는 것입니다.

---

## 6. 추상화의 대가

하지만 추상화에는 대가도 있습니다.

추상화 계층이 높아질수록, 정확히 무슨 일이 일어나는지에 대한 통제력은 줄어듭니다.
C 프로그래머는 프로그램이 정확히 얼마나 많은 메모리를 사용하는지 결정할 수 있습니다.
Python 프로그래머는 그것을 Python 자체에 맡깁니다.

대부분의 애플리케이션에서는 그것이 전혀 문제가 되지 않습니다. 하지만 1밀리초 하나하나가 중요한 시스템 — 운영체제, 게임 엔진, 임베디드 하드웨어 — 에서는, 더 낮은 계층을 선택하게 됩니다.

개발자로서, 당신은 자신의 문제에 어떤 계층이 적합한지를 선택하는 법을 배우게 됩니다.
