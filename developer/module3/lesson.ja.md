# モジュール3 — 言語と抽象化

あなたがPythonを書くとき、実はコンピューターと直接会話しているわけではありません。
あなたはPythonと会話しています。PythonはCと会話しています。CはアセンブリAと会話しています。アセンブリはプロセッサーと会話しています。

それぞれの層は、その下の層の複雑さを覆い隠しています。これを**抽象化（abstraction）**と呼びます——そしてこれは、コンピューターサイエンスの中でも最も強力なアイデアのひとつです。

---

## 1. コンピューターは0と1しか話さない

もっとも深いレベルでは、コンピューターはたったひとつのことしか理解していません：電流があるか、ないか。オンか、オフか。1か、0か。

あなたがこれまでに書くあらゆるコードは、最終的には1と0の長い並びに変換されます——これが**機械語**です。

機械語で書いた単純な足し算は、こんな見た目になります：
```
10110000 01100001
00000101 00000001
10100010 01100001
```

これこそが、プロセッサーが実際に実行しているものです。人間はこれを、間違えずに書いたり読んだりすることはできません。だからこそ、次の層が発明されたのです。

---

## 2. アセンブリ——命令に名前をつける

1950年代、プログラマーたちはこう考えました。よく使う命令に、名前をつけたらどうだろうか、と。

`10110000 01100001` の代わりに、こう書きます：
```asm
MOV AL, 1
ADD AL, 1
MOV メモリ, AL
```

`MOV`は「値を移動する」という意味です。`ADD`は「加算する」という意味です。
これらは、0と1で表された命令とまったく同じものです——ただし、人間にも読める形になっています。

**アセンブラ**は、アセンブリコードを機械語に変換します。

アセンブリは、大きな前進でした。しかし依然としてハードウェアに近い存在でした——自分がどれだけのメモリを持っているか、どのレジスタが使えるか、プロセッサーがどう組み立てられているかを、正確に知っておく必要がありました。

---

## 3. 高水準言語——人間のために書く

1950年代から60年代にかけて、新しい考え方が生まれました。もっと人間の言語に近いコードを書けたら、どうだろうか？

**FORTRAN**（1957年）——科学計算のために：
```fortran
X = A + B * C
```

**COBOL**（1959年）——ビジネス用途のために：
```cobol
ADD SALARY TO TOTAL-WAGES
```

**C**（1972年）——コンパクトで強力、ハードウェアに近いながらも読みやすい：
```c
int som = a + b;
```

**Python**（1991年）——ほとんど英語のように読める、圧倒的な読みやすさ：
```python
som = a + b
```

言語の世代が進むごとに、より読みやすくなっていきました。そして、進むごとに、より多くの複雑さが覆い隠されていったのです。

## 4. コンパイラとインタープリタ——翻訳者たち

人間にも読めるコードは、どうやってプロセッサーにたどり着くのでしょうか？

それは、**コンパイラ**または**インタープリタ**を通してです。

**コンパイラ**——プログラムを実行する前に、コード全体を一度に機械語へ翻訳します。
利点：プログラムの動作が速い。
欠点：変更のたびに再コンパイルが必要。
例：C、C++、Rust。

**インタープリタ**——プログラムが動いている最中に、コードを1行ずつ翻訳していきます。
利点：変更の結果をすぐに確認できる。
欠点：やや動作が遅い。
例：Python、JavaScript、Ruby。

開発者として出会うことになる言語の多くは、インタープリタ型です——PythonもJavaScriptも、どちらもそうです。これは学習にとって都合が良いことです：1行書くたびに、何が起こるかをすぐに確認できるからです。

---

## 5. なぜ抽象化はこれほど強力なのか？

想像してみてください。もしウェブサイトを作るたびに、画面にテキストを表示するためだけに、機械語のコードを一から全部書かなければならないとしたら？あなたは「Hello world」から先には、決して進めなかったでしょう。

抽象化があるからこそ、**他の人がすでに築いたものの上に、さらに積み上げていくこと**ができるのです。

Pythonは、Cで書かれています。
Cは、アセンブリで書かれています。
アセンブリは、機械語で書かれています。
機械語は、トランジスタによって実行されます。
トランジスタは、電気技術者によって設計されています。

役に立つプログラムを書くために、あなたはこれらすべてを知っている必要はありません。あなたは、他の人がすでに築いた層を利用しているのです。

これはまた、オープンソースの背後にある考え方でもあります：次の人がさらにその先を築けるように、コードを共有すること。

---

## 6. 抽象化の代償

しかし、抽象化には代償もあります。

抽象化の層が高くなればなるほど、実際に何が起きているかへのコントロールは少なくなっていきます。
Cのプログラマーは、プログラムがどれだけのメモリを使っているかを、正確に決めることができます。
Pythonのプログラマーは、それをPython自身に任せています。

ほとんどの用途では、それはまったく問題になりません。しかし、1ミリ秒たりとも無駄にできないシステム——オペレーティングシステム、ゲームエンジン、組み込みハードウェア——では、より低い層を選ぶことになります。

開発者として、あなたは自分の抱える問題に、どの層が合っているのかを選ぶことを学んでいきます。
