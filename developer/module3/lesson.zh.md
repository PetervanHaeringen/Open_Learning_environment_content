# 模块3 — 语言与抽象

当你写Python代码时，你并不是真的在和计算机对话。
你是在和Python对话。Python和C对话。C和汇编语言对话。汇编语言和处理器对话。

每一层都隐藏了它下面那一层的复杂性。这就叫**抽象（abstraction）**——它是计算机科学中最强大的思想之一。

---

## 1. 计算机只懂零和一

在最底层，计算机只能理解一件事：有电流，还是没有电流。开，还是关。1，还是0。

你写下的任何代码，最终都会被转换成一长串1和0——这就是**机器语言**。

用机器语言写的一个简单加法，长这样：
```
10110000 01100001
00000101 00000001
10100010 01100001
```

这就是处理器实际执行的东西，一字不差。人类无法在不出错的情况下书写或阅读这种代码。所以，才有了下一层的诞生。

---

## 2. 汇编语言——给指令起名字

在20世纪50年代，程序员们想到：为什么不给最常用的指令起个名字呢？

不再写 `10110000 01100001`，而是写：
```asm
MOV AL, 1
ADD AL, 1
MOV 内存, AL
```

`MOV` 的意思是"移动一个值"。`ADD` 的意思是"相加"。
这些和那一串0和1指的是完全相同的指令——只不过，人类能读懂了。

**汇编器（assembler）**负责把汇编代码转换成机器语言。

汇编语言是巨大的进步。但它仍然和硬件贴得很近——你依然需要精确知道自己有多少内存、有哪些寄存器可用、处理器的内部结构是怎样的。

---

## 3. 高级语言——为人类而写

20世纪50到60年代，出现了一个新想法：如果写出的代码更像人类语言，会怎么样？

**FORTRAN**（1957年）——用于科学计算：
```fortran
X = A + B * C
```

**COBOL**（1959年）——用于商业应用：
```cobol
ADD SALARY TO TOTAL-WAGES
```

**C语言**（1972年）——紧凑、强大，贴近硬件却又可读：
```c
int som = a + b;
```

**Python**（1991年）——可读性极高，几乎就像英语一样：
```python
som = a + b
```

每一代编程语言都变得更易读。而每前进一步，就多隐藏了一层复杂性。

## 4. 编译器与解释器——翻译者

可读的代码，是怎么到达处理器手中的？

答案是：通过**编译器（compiler）**或**解释器（interpreter）**。

**编译器**——在程序运行之前，把整段代码一次性翻译成机器语言。
优点：程序运行速度快。
缺点：每次改动都要重新编译。
例子：C、C++、Rust。

**解释器**——在程序运行的同时，一行一行地翻译代码。
优点：改动之后能立刻看到结果。
缺点：运行速度稍慢。
例子：Python、JavaScript、Ruby。

作为开发者，你会接触到的大多数语言都是解释型的——Python和JavaScript都是。这对学习来说非常方便：你写一行代码，就能立刻看到发生了什么。

---

## 5. 为什么抽象如此强大？

想象一下：如果每次搭建一个网站，你都必须为了在屏幕上显示一段文字，从头写出完整的机器语言代码，那你可能永远也做不出比"Hello world"更复杂的东西。

抽象让我们能够**在别人已经搭建好的成果之上继续building（建造）**。

Python是用C写的。
C是用汇编语言写的。
汇编语言是用机器语言写的。
机器语言由晶体管执行。
晶体管是由电气工程师设计的。

要写出一个能做点有用的事情的程序，你完全不需要了解这一切。你只需要使用别人已经搭好的那些层。

这也正是开源精神背后的理念：分享代码，让下一个人能够在此基础上继续构建。

---

## 6. 抽象的代价

但抽象也是有代价的。

抽象层越高，你对具体发生了什么的控制权就越少。
一个C语言程序员可以精确地控制一个程序究竟用了多少内存。
而一个Python程序员，则把这件事交给了Python去处理。

对大多数应用来说，这完全无关紧要。但对于那些每一毫秒都至关重要的系统——操作系统、游戏引擎、嵌入式硬件——你就需要选择更底层的那一层了。

作为开发者，你要学会的，正是根据自己面对的问题，选择合适的那一层。
