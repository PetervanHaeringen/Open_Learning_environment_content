# モジュール5 — コンピューターなしでプログラミングする

コードは、読むだけでは理解できません。実際に*やってみる*ことで、初めて理解できるのです。
このモジュールでは、カード、役割分担、そしてあなた自身の体を使って、アルゴリズムを演じてみます。

---

## 用意するもの

- カードまたは付箋（最低20枚）
- マーカー
- 参加人数：3〜8人
- 任意：床に貼る「メモリの場所」を示すテープ

---

## ゲームの役割

| 役割 | 仕事 |
|-----|------|
| **プロセッサ（Processor）** | 命令をひとつずつ実行する |
| **メモリ（Memory）** | 値（変数）が書かれたカードを持つ |
| **入力（Input）** | プログラムが求めたときに、新しい値を渡す |
| **出力（Output）** | プログラムが「出力」した内容を書き留める |
| **プログラム（Program）** | 命令をひとつずつ、声に出して読み上げる |

---

## ゲーム1 — 変数と足し算

**プログラム内容：**
```
1. 値5を「x」として保存する
2. 値3を「y」として保存する
3. x + y を計算する
4. 結果を「合計」として保存する
5. 「合計」を出力する
```

**ゲームの流れ：**
- メモリがカードに「x = 5」と書き、それを持つ
- メモリがカードに「y = 3」と書き、それを持つ
- プロセッサがメモリに尋ねる：「xは何ですか？」→ メモリがカードを見せる
- プロセッサが尋ねる：「yは何ですか？」→ メモリがカードを見せる
- プロセッサが 5 + 3 = 8 を計算する
- メモリが新しいカードに「合計 = 8」と書く
- 出力がボードに「8」と書く

**ふりかえり：** もしステップ1で「x = 5」を「x = 10」に変えたら、何が起こるでしょうか？誰が何を調整しますか？

---

## ゲーム2 — 条件分岐（if/else）

**プログラム内容：**
```
1. ユーザーに数値を尋ねる → 「数値」として保存する
2. もし数値が10より大きければ：
       「大きい」と出力する
   そうでなければ：
       「小さい」と出力する
```

**ゲームの流れ：**
- 入力がある数値（例えば7）を選び、それをカードに書く
- メモリがそれを「数値 = 7」として保存する
- プロセッサが尋ねる：「7は10より大きいですか？」→ いいえ
- プロセッサは「そうでなければ」の分岐へ進む
- 出力が「小さい」と書く

異なる数値で3回やってみましょう。プロセッサの振る舞いには、どんな変化がありますか？

---

## ゲーム3 — ループ（繰り返し）

**プログラム内容：**
```
1. 値1を「カウンター」として保存する
2. カウンターが5以下である間：
       カウンターを出力する
       カウンターを1増やす
3. 終了
```

**ゲームの流れ：**
- メモリは「カウンター = 1」から始まる
- プロセッサが確認する：1 ≤ 5 か？はい → 出力が「1」と書き、カウンターは2になる
- プロセッサが確認する：2 ≤ 5 か？はい → 出力が「2」と書き、カウンターは3になる
- ……（カウンターが6になるまで続ける）
- プロセッサが確認する：6 ≤ 5 か？いいえ → 停止

**ふりかえり：** もしステップ3——「カウンターを1増やす」——を忘れていたら、何が起きるでしょうか？実際に試してみましょう。

*（これは**無限ループ**です——プログラムが決して止まらなくなります。これはよくある間違いです。）*

---

## ゲーム4 — 並べ替え（アルゴリズムを演じてみる）

これは定番のアルゴリズムです：**バブルソート（Bubble Sort）**。

**準備：**
- カードに5つのランダムな数字を書きます：例えば 4、1、7、2、9
- それらをテーブルの上に一列に並べます

**アルゴリズムの内容：**
```
何も変化がなくなるまで繰り返す：
    隣り合うそれぞれのペアについて：
        もし左の数字が右の数字より大きければ：
            それらを入れ替える
```

**ゲームの流れ：**
- 第1ラウンド：4と1を比較 → 4 > 1、入れ替える → [1, 4, 7, 2, 9]
- 4と7を比較 → 4 < 7、入れ替えない
- 7と2を比較 → 7 > 2、入れ替える → [1, 4, 2, 7, 9]
- 7と9を比較 → 7 < 9、入れ替えない
- 第2ラウンド：また最初からやり直す……
- 1ラウンドを通して入れ替えがまったく起きなくなるまで続ける

**ふりかえり：**
- 何ラウンド必要でしたか？
- 「最悪のケース」とは何でしょうか——どの並び順が、最も多くの手順を必要としますか？
- もっと速いやり方を思いつきますか？

---

## 実際のコードとのつながり

これらのゲームを経験した後には、コードの中でこれらの概念に出会ったとき、すぐに気づけるようになります。

| ゲームの中でやったこと | コードでの表現 |
|--------------------------|---------|
| 値が書かれたカードを持つこと | `x = 5`（変数） |
| 「もしこうなら、こうする」 | `if / else` |
| 条件が成り立たなくなるまで繰り返すこと | `while` ループ |
| 一列に並んだものを順に処理すること | `for` ループ |
| ステップを忘れて、止まらなくなること | 無限ループ（バグ） |

次のモジュールでは、これらすべてを、あなた自身の手で書いていきます——ただし、今度は本物のプログラミング言語を使って。
