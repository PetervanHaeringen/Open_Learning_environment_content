# 모듈 5 — 컴퓨터 없이 프로그래밍하기

코드는 읽는 것만으로는 이해할 수 없습니다. *직접 해보면서* 이해하게 됩니다.
이 모듈에서는 카드, 역할, 그리고 당신 자신의 몸을 사용해서 알고리즘을 직접 연기해 봅니다.

---

## 준비물

- 카드 또는 포스트잇 (최소 20장)
- 마커
- 참가자: 3~8명
- 선택 사항: 바닥에 "메모리 자리"를 표시할 테이프

---

## 게임 역할

| 역할 | 임무 |
|-----|------|
| **프로세서(Processor)** | 명령을 하나씩 실행합니다 |
| **메모리(Memory)** | 값(변수)이 적힌 카드를 들고 있습니다 |
| **입력(Input)** | 프로그램이 요청할 때 새로운 값을 제공합니다 |
| **출력(Output)** | 프로그램이 "출력"하는 내용을 적습니다 |
| **프로그램(Program)** | 명령을 하나씩 소리 내어 읽습니다 |

---

## 게임 1 — 변수와 덧셈

**프로그램 내용:**
```
1. 값 5를 "x"로 저장한다
2. 값 3을 "y"로 저장한다
3. x + y를 계산한다
4. 결과를 "합계"로 저장한다
5. "합계"를 출력한다
```

**게임 진행:**
- 메모리가 카드에 "x = 5"라고 적고 들고 있습니다
- 메모리가 카드에 "y = 3"이라고 적고 들고 있습니다
- 프로세서가 메모리에게 묻습니다: "x가 뭐예요?" → 메모리가 카드를 보여줍니다
- 프로세서가 묻습니다: "y가 뭐예요?" → 메모리가 카드를 보여줍니다
- 프로세서가 5 + 3 = 8을 계산합니다
- 메모리가 새 카드에 "합계 = 8"이라고 적습니다
- 출력이 보드에 "8"이라고 적습니다

**마무리 토론:** 1단계에서 "x = 5"를 "x = 10"으로 바꾸면 무슨 일이 일어날까요? 누가 무엇을 조정해야 할까요?

---

## 게임 2 — 조건 (if/else)

**프로그램 내용:**
```
1. 사용자에게 숫자를 묻는다 → "숫자"로 저장한다
2. 만약 숫자가 10보다 크면:
       "크다"를 출력한다
   그렇지 않으면:
       "작다"를 출력한다
```

**게임 진행:**
- 입력이 숫자를 하나 고르고(예: 7), 카드에 적습니다
- 메모리가 그것을 "숫자 = 7"로 저장합니다
- 프로세서가 묻습니다: "7이 10보다 크나요?" → 아니요
- 프로세서는 "그렇지 않으면" 쪽으로 갑니다
- 출력이 "작다"라고 적습니다

서로 다른 숫자로 세 번 해보세요. 프로세서의 행동에서 무엇이 달라지나요?

---

## 게임 3 — 반복문 (Loop)

**프로그램 내용:**
```
1. 값 1을 "카운터"로 저장한다
2. 카운터가 5 이하인 동안:
       카운터를 출력한다
       카운터를 1 증가시킨다
3. 완료
```

**게임 진행:**
- 메모리는 "카운터 = 1"로 시작합니다
- 프로세서가 확인합니다: 1 ≤ 5인가요? 예 → 출력이 "1"이라고 적고, 카운터는 2가 됩니다
- 프로세서가 확인합니다: 2 ≤ 5인가요? 예 → 출력이 "2"라고 적고, 카운터는 3이 됩니다
- ... (카운터가 6이 될 때까지 계속합니다)
- 프로세서가 확인합니다: 6 ≤ 5인가요? 아니요 → 멈춥니다

**마무리 토론:** 만약 3단계 — "카운터를 1 증가시킨다" — 를 잊어버렸다면 무슨 일이 일어날까요? 직접 해보세요.

*(이것이 바로 **무한 루프(infinite loop)**입니다 — 프로그램이 절대 멈추지 않습니다. 이것은 아주 흔한 실수입니다.)*

---

## 게임 4 — 정렬 (알고리즘을 연기하기)

이것은 고전적인 알고리즘입니다: **버블 정렬(Bubble Sort)**.

**준비:**
- 카드에 무작위 숫자 5개를 적습니다: 예를 들어 4, 1, 7, 2, 9
- 그것들을 테이블 위에 한 줄로 늘어놓습니다

**알고리즘 내용:**
```
더 이상 아무것도 바뀌지 않을 때까지 반복한다:
    서로 인접한 각 쌍에 대해:
        만약 왼쪽 숫자가 오른쪽 숫자보다 크면:
            둘을 교환한다
```

**게임 진행:**
- 1라운드: 4와 1을 비교 → 4 > 1, 교환 → [1, 4, 7, 2, 9]
- 4와 7을 비교 → 4 < 7, 교환하지 않음
- 7과 2를 비교 → 7 > 2, 교환 → [1, 4, 2, 7, 9]
- 7과 9를 비교 → 7 < 9, 교환하지 않음
- 2라운드: 처음부터 다시...
- 한 라운드 전체에서 더 이상 교환이 일어나지 않을 때까지 계속합니다

**마무리 토론:**
- 몇 라운드가 필요했나요?
- "최악의 경우"란 무엇인가요 — 어떤 순서가 가장 많은 단계를 필요로 하나요?
- 더 빠른 방법을 생각해낼 수 있나요?

---

## 실제 코드와의 연결

이 게임들을 해본 후에는, 코드에서 이 개념들을 마주쳤을 때 바로 알아볼 수 있게 됩니다:

| 게임에서 한 일 | 코드에서는 |
|--------------------------|---------|
| 값이 적힌 카드를 들고 있기 | `x = 5` (변수) |
| "이러면, 저렇게" | `if / else` |
| 조건이 더 이상 성립하지 않을 때까지 반복하기 | `while` 반복문 |
| 한 줄을 따라 진행하기 | `for` 반복문 |
| 한 단계를 잊어버려서 멈추지 않게 되는 것 | 무한 루프 (버그) |

다음 모듈에서는 이 모든 것을 직접 작성하게 됩니다 — 이번에는 실제 프로그래밍 언어로요.
