# 模块5 — 不用电脑也能"编程"

代码不是靠读就能理解的。你需要靠亲身*去做*才能真正理解。
在这个模块中，你将用卡片、角色扮演和自己的身体，把算法演出来。

---

## 所需材料

- 卡片或便利贴（至少20张）
- 记号笔
- 参与人数：3到8人
- 可选：地板上贴胶带，标出"内存位置"

---

## 游戏角色

| 角色 | 任务 |
|-----|------|
| **处理器（Processor）** | 逐条执行指令 |
| **内存（Memory）** | 拿着写有数值的卡片（变量） |
| **输入（Input）** | 当程序请求时，提供新的数值 |
| **输出（Output）** | 把程序"打印"出来的内容写下来 |
| **程序（Program）** | 一条一条地朗读指令 |

---

## 游戏1 — 变量与加法

**程序内容：**
```
1. 把数值5存为"x"
2. 把数值3存为"y"
3. 计算 x + y
4. 把结果存为"sum"
5. 打印"sum"
```

**游戏过程：**
- 内存在卡片上写下"x = 5"，并拿着它
- 内存在卡片上写下"y = 3"，并拿着它
- 处理器问内存："x是多少？" → 内存出示卡片
- 处理器问："y是多少？" → 内存出示卡片
- 处理器计算 5 + 3 = 8
- 内存在一张新卡片上写下"sum = 8"
- 输出在黑板上写下"8"

**讨论总结：** 如果在第1步把"x = 5"改成"x = 10"，会发生什么？谁需要相应地做出调整？

---

## 游戏2 — 条件判断（if/else）

**程序内容：**
```
1. 向用户询问一个数字 → 存为"数字"
2. 如果 数字 大于 10：
       打印"大"
   否则：
       打印"小"
```

**游戏过程：**
- 输入选择一个数字（比如7），把它写在卡片上
- 内存把它存为"数字 = 7"
- 处理器问："7大于10吗？" → 不是
- 处理器走向"否则"这个分支
- 输出写下"小"

用不同的数字玩三次。处理器的行为会有什么变化？

---

## 游戏3 — 循环（重复）

**程序内容：**
```
1. 把数值1存为"计数器"
2. 只要 计数器 小于等于 5：
       打印 计数器
       把 计数器 加1
3. 完成
```

**游戏过程：**
- 内存从"计数器 = 1"开始
- 处理器检查：1 ≤ 5 吗？是的 → 输出写下"1"，计数器变成2
- 处理器检查：2 ≤ 5 吗？是的 → 输出写下"2"，计数器变成3
- ……（继续，直到计数器 = 6）
- 处理器检查：6 ≤ 5 吗？不是 → 停止

**讨论总结：** 如果我们忘记了第3步——"把计数器加1"——会发生什么？动手试一试。

*（这就是所谓的**无限循环**——程序永远不会停止。这是一个非常常见的错误。）*

## 游戏4 — 排序（演出一个算法）

这是一个经典算法：**冒泡排序（Bubble Sort）**。

**准备工作：**
- 在卡片上写下5个随机数字，比如：4、1、7、2、9
- 把它们排成一排放在桌上

**算法内容：**
```
重复，直到什么都不再变化为止：
    对每一对相邻的数字：
        如果左边的数字比右边的大：
            交换它们
```

**游戏过程：**
- 第1轮：比较4和1 → 4 > 1，交换 → [1, 4, 7, 2, 9]
- 比较4和7 → 4 < 7，不交换
- 比较7和2 → 7 > 2，交换 → [1, 4, 2, 7, 9]
- 比较7和9 → 7 < 9，不交换
- 第2轮：从头再来一遍……
- 一直持续，直到有一整轮不再发生任何交换为止

**讨论总结：**
- 你用了几轮才排好？
- "最坏情况"是什么——哪种初始顺序需要最多的步骤？
- 你能想出一种更快的方法吗？

## 与真实代码的联系

玩过这些游戏之后，当你在代码中遇到这些概念时，就能一眼认出它们：

| 你在游戏中做的事 | 对应的代码 |
|--------------------------|---------|
| 拿着写有数值的卡片 | `x = 5`（变量） |
| "如果这样，那么那样" | `if / else` |
| 重复，直到某个条件不再成立 | `while` 循环 |
| 遍历一排内容 | `for` 循环 |
| 忘了某一步，导致程序停不下来 | 无限循环（bug） |

在下一个模块中，你将亲自把这一切都写出来——不过这次是用真正的编程语言。
