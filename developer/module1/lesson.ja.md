# モジュール1 — プログラマーとしての人間

コードを1行も書く前に、人間が何千年もの間ずっとやってきたことに、少し立ち止まって考えてみましょう。それは、他の人や機械に「何をすべきか」を伝えることです。

プログラミングは、そのひとつの特別な形です。しかし、それはコンピューターから始まったわけではありません。

## 1. ピーナッツバターの実験

想像してみてください。ある子どもが、父親に向けて指示を書きました。

> 「パンにピーナッツバターを乗せて。」

父親はピーナッツバターの瓶を手に取ります。そして、それをパンの上に置きます。開けもせず、ナイフも使わずに。まさに書かれていた通りに。

子どもは呆然としてしまいます。しかし、父親は何も間違ったことをしていません——書かれていたことを、そのまま正確に実行しただけなのです。

この実験は、プログラミングの本質を示しています：**あなたが「意図していること」と、実際に「言っていること」の間にあるギャップ**です。

人間は、足りない部分を自動的に補います。しかしコンピューターはそうしません。コンピューターは、あなたが言ったことをそのまま実行します——多くもなく、少なくもなく、その中間の何かでもなく。

## 2. 指示はいたるところにある

コンピューターが登場するはるか以前から、人間はすでに「プログラム」を書いていました。ただ、それを別の名前で呼んでいただけです。

**レシピ**は、料理人のためのプログラムです。
材料は入力（インプット）です。手順は指示です。出来上がった料理は出力（アウトプット）です。

**楽譜**は、音楽家のためのプログラムです。
音符が指示です：どんな音を、どのくらいの長さで、どのくらいの強さで、いつ演奏するか。

**法律**は、社会のためのプログラムです。
状況Xが発生すれば、それに続いて行動Yが取られます。

**チェスの戦略**は、プレイヤーのためのプログラムです。
相手がこうしたら、こうする、というように。

これらのシステムにはすべて共通することがあります：**何が起こるべきかを、一歩ずつ、あいまいさなく**記述しているという点です。

それこそが、アルゴリズムの本質です。

## 3. 何が指示を「正確」にするのか？

同じレシピの、2つのバージョンを見比べてみましょう。

**バージョンA——曖昧：**
> 「ボウルに小麦粉を少し入れて、水を少し加えて、いい感じになるまで混ぜる。」

**バージョンB——正確：**
> 「ボウルに小麦粉200グラムを入れる。水120mlを加える。生地がなめらかになり、ボウルにくっつかなくなるまで、3分間混ぜる。」

バージョンAは、経験豊富なパン職人には通用します——足りない部分を自分で補えるからです。
バージョンBは、これまでパンを焼いたことがない人にも通用します。

コンピューターは、常に初心者です。「言いたいことをわかってくれる」と決して期待してはいけません。

## 4. もう一つの側面：同じ目的地に至る、複数の道

しかし、これとは逆の問題もあります。

想像してみてください。あなたは誰かに、アムステルダムからユトレヒトまで行くよう頼みます。
あなたはA2号線を思い浮かべています。彼女は電車を使います。3人目の人は自転車で行きます。

3人とも、目的地に到着します。指示自体は正しかったのです。ただ、実行の仕方が違っただけです。

これは、人間はするけれど、コンピューターは自分からはしないことです：**同じ目標に至る、別の道を見つけ出すこと**です。

開発者として、あなたはこれを意識的に設計することを学んでいきます。あなたのプログラムは動かなければなりませんが、それを書く方法は常に複数あります。それぞれに、それぞれの長所と短所があります。

## 5. アルゴリズムとは何か？

アルゴリズムとは、次のような性質を持つ一連の手順のことです：

- 始まりがある
- 終わる（必ず終わる。「たぶん終わる」ではない）
- どんな状況でも、次に何をすべきかが明確である
- 同じ入力に対しては、常に同じ結果を返す

形式ばって聞こえるかもしれません。しかし、あなたは毎日アルゴリズムを使っています。

お茶をどうやって淹れますか？
1. 電気ケトルに水を入れる。
2. ケトルのスイッチを入れる。
3. お湯が沸くまで待つ。
4. ティーバッグにお湯を注ぐ。
5. 3分間待つ。
6. ティーバッグを取り出す。
7. 完成。

これがアルゴリズムです。一歩ずつ。あいまいさなく。何度でも繰り返せる。

## 6. なぜこれがプログラミングの土台なのか？

Python、JavaScript、Java、Cなど、あらゆるプログラミング言語は、突き詰めれば、コンピューターが実行できる形でアルゴリズムを書き表すための手段にすぎません。

言語はいわば「綴り方」です。アルゴリズムこそが「思考」そのものです。

すべての言語を知らなくても、優れた開発者にはなれます。しかし、手順で、場合分けで、そして入力と出力で物事を考えられなければ、良い開発者にはなれません。

その思考は、ここから始まります。ターミナルや画面の前からではなく——**どうすれば誤解の余地がまったくないほど、明確に説明できるだろうか？**という問いから始まるのです。
