# 모듈 2 — 내부 작동 원리

이제 Git이 *왜* 존재하는지 알게 되었습니다.
이 모듈은 한 단계 더 깊이 들어갑니다: *내부에서 실제로 어떻게 작동하는가?*

이것을 이해하기 위해 프로그래머일 필요는 없습니다.
하지만 한 번 이해하면, 무언가 잘못되었을 때 더 이상 당황하지 않을 것입니다.

---

## 1. .git 폴더: 프로젝트의 기억

폴더에서 `git init`을 실행하면 Git은 하나의 숨겨진 폴더를 생성합니다: `.git`

이 폴더에는 Git이 프로젝트에 대해 알고 있는 모든 것이 포함되어 있습니다:
- 모든 커밋
- 모든 브랜치
- 모든 설정
- 완전한 기록

`.git` 폴더를 삭제하면 역사 없는 평범한 폴더가 됩니다.
`.git` 폴더는 그 프로젝트에 대해 *Git 그 자체*입니다.

> **직접 해보기 (선택):** Git 저장소에서 터미널을 열고 `ls -la`를 입력하세요.
> `.git` 폴더가 보일 것입니다. 그 다음 `ls .git`를 입력하여 내용을 확인해 보세요.

---

## 2. 모든 것은 객체입니다

Git은 하드 드라이브처럼 "파일"을 저장하지 않습니다.
Git은 **객체**를 저장합니다. 객체에는 네 가지 종류가 있습니다:

| 종류 | 내용 |
|------|-----------|
| **blob** | 하나의 파일 내용 |
| **tree** | 폴더: 어떤 blob과 tree가 포함되어 있는지 |
| **commit** | 스냅샷: 어떤 tree인지, 누가, 언제, 메시지 |
| **tag** | 특정 커밋을 가리키는 이름 |

모든 객체는 고유한 이름, 즉 **해시(hash)**를 받습니다.

---

## 3. 해시란 무엇인가?

해시는 객체의 *내용*을 기반으로 Git이 계산하는 코드입니다.

예시: `Hello, Git!`이라는 텍스트는 항상 동일한 해시를 생성합니다.
한 글자만 바꿔도 해시는 완전히 달라집니다.

```
echo "Hello, Git!" | git hash-object --stdin
# 다음과 같은 결과를 출력합니다: a8c9f4b2d3...
```

Git은 해시(SHA-1)를 다음 목적으로 사용합니다:
- 객체를 고유하게 식별
- 무언가 변경되었거나 손상되었는지 감지
- 한 커밋에서 다른 커밋으로 참조

![해시 원리: 작은 변경이라도 해시는 완전히 다르다](/instructions/content-images/git/module2//hash_principe.svg)

## 4. 스냅샷, 차이가 아님

많은 사람들은 Git이 버전 간의 *차이*를 저장한다고 생각합니다.
하지만 그것은 정확하지 않습니다.

Git이 저장하는 것은 **스냅샷**——파일이 특정 순간에 어떻게 보이는지의 완전한 기록입니다.

하지만 똑똑하게 처리합니다: 파일에 변경이 없으면 Git은 해당 파일의 이전 버전에 대한 참조만 저장합니다. 중복은 만들지 않습니다.

결과: 완전하면서도 효율적입니다.

## 5. 커밋 그래프

모든 커밋은 자신이 어떤 커밋에서 파생되었는지——자신의 "부모(parent)"——를 알고 있습니다.
이렇게 커밋의 연쇄가 형성됩니다.

```
A ← B ← C ← D   (main)
```

브랜치를 생성하면 이 연쇄가 분기됩니다:

```
A ← B ← C ← D         (main)
          ↖
            E ← F     (feature-branch)
```

이것을 **DAG**: 방향성 비순환 그래프(Directed Acyclic Graph)라고 부릅니다.
방향성(오래된 것에서 새로운 것으로)이 있고, 비순환(루프가 없음)입니다.

HEAD는 *"당신이 지금 어디에 있는지"*를 알려주는 참조입니다.
보통 HEAD는 브랜치의 끝(tip)을 가리킵니다.

![브랜치와 HEAD가 포함된 커밋 그래프](/instructions/content-images/git/module2/commit_graaf.svg)

## 6. 왜 이것을 알아두면 유용한가?

이 지식을 매일 적극적으로 사용하는 것은 아닙니다.
하지만 Git이 내부에서 어떻게 작동하는지 이해하면 다음을 알게 됩니다:

- 왜 두 브랜치가 안전하게 나란히 존재할 수 있는지
- 왜 Git이 이렇게 빠른지(모든 것이 로컬이고 해시화되어 있기 때문)
- 왜 커밋은 변경 불가능한지(해시가 내용을 보증하기 때문)
- "이전 커밋으로 돌아가라"고 할 때 그것이 무엇을 의미하는지

Git은 마법이 아닙니다. 객체와 참조로 이루어진 영리한 시스템입니다.
