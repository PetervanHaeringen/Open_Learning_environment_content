# モジュール3 — バージョン管理を図で見る

コマンドを入力する前に、それを*見える化*できる必要があります。
このモジュールでは、頭の中のモデルを作っていきます。Gitを図に描くと、どんな形になるでしょうか？

---

## 1. タイムライン：一列に並んだコミット

Gitの最もシンプルな状態は、コミットが一直線に並んだ形です。
それぞれのコミットはスナップショットであり、それぞれが自分の前のコミットを指しています。

```
○ — ○ — ○ — ○ — ○
A   B   C   D   E
```

- **A** は最初のコミット（起点）
- **E** は最新のコミット（現在の状態）
- 矢印は過去を指している

タイムラインは左から右に読みます。これが、履歴が育ってきた順序です。

![Gitのタイムライン——一列に並んだコミット](images/tijdlijn_lineair.png)

---

## 2. ブランチ：横に伸びる道

想像してみてください。あなたは、本流に手を加えずに何かを試したいとします。
そこで**ブランチ**を作ります——既存のコミットから始まる、横に伸びる道です。

```
○ — ○ — ○ — ○ — ○       (main)
              |
              ○ — ○       (experiment)
```

- `main` はそのまま進み続ける
- `experiment` はコミットDから始まり、独立して育っていく
- 両方が同時に存在し、互いに影響を与えない

Gitにおいて、ブランチとは、あるコミットを指す名前にすぎません。
それだけです。ファイルのコピーもなく、重複したフォルダもありません——ただのラベルです。

![タイムラインから枝分かれしたブランチ](images/branch_zijtak.png)

---

## 3. マージ：2つのブランチを合わせる

実験が終わったら、それを`main`に戻したくなります。
これを**マージ**と呼びます。

```
○ — ○ — ○ — ○ — ○ — ○   (main、マージ後)
              |       |
              ○ — ○ ——   (experiment、マージ済み)
```

Gitは共通の祖先（コミットD）と2つの末端を見比べます。
そして変更内容を組み合わせ、新しい**マージコミット**を作成します（mainの一番最後の○）。

もし同じ行が両方のブランチで変更されていたら → コンフリクト（衝突）が発生します。
そうでなければ → 自動的にマージされます。

![2つのブランチのマージ](images/merge_visueel.png)

---

## 4. HEAD：あなたは今ここにいる

`HEAD`とは、あなたが今グラフのどこにいるかを示すシールのようなものです。

```
○ — ○ — ○ — ○ — ○
                 ↑
                HEAD (main)
```

別のブランチに切り替えると（`git switch experiment`）、このシールも一緒に移動します。

```
○ — ○ — ○ — ○ — ○       (main)
              |
              ○ — ○
                   ↑
                  HEAD (experiment)
```

今あなたがコミットするものはすべて、HEADが指しているブランチに入ります。

---

## 5. 過去に戻る

例えば、コミットCに、今調べたいバグが含まれていたとします。
一時的にHEADをCに移動させることができます（`git checkout C`）。

```
○ — ○ — ○ — ○ — ○
         ↑
        HEAD (detached)
```

そうすると、ファイルはその時点の状態のまま表示されます。
Gitはこれを「detached HEAD（切り離されたHEAD）」と呼びます——あなたはブランチの上ではなく、コミットの上に直接立っている状態です。

見るだけなら便利です。しかし、新しいブランチを作らずにコミットしてしまうのは危険です。

---

## 6. 演習：自分で描いてみよう

ペンと紙を用意してください。

1. 5つの円（コミットA〜E）で一直線を描く。
2. Cから始まるブランチを描き、さらに2つコミットを追加する。
3. Eのあとに、本流へ戻るマージを描く。
4. HEADのシールを正しい位置に置く。

この絵こそが、Gitが内部で実際に管理している内容そのものです。
次のモジュールでは、これをカードを使ってもう一度演じてみます。
