# Модуль 3 — Контроль версий в картинках

Прежде чем вводить команду, нужно уметь её *увидеть*.
В этом модуле мы строим мысленную модель: как выглядит Git, если его нарисовать?

---

## 1. Временная шкала: коммиты в ряд

Самая простая ситуация в Git — это прямая линия коммитов.
Каждый коммит — снимок. Каждый коммит указывает назад, на своего предшественника.

```
○ — ○ — ○ — ○ — ○
A   B   C   D   E
```

- **A** — первый коммит (начало)
- **E** — последний коммит (текущее состояние)
- Стрелки указывают в прошлое

Читайте временную шкалу слева направо: именно так росла история.

![Временная шкала Git — коммиты в ряд](images/tijdlijn_lineair.png)

## 2. Ветка (branch): боковой путь

Представьте: вы хотите что-то попробовать, не затрагивая основную линию.
Вы создаёте **ветку** — боковой путь, который начинается от уже существующего коммита.

```
○ — ○ — ○ — ○ — ○       (main)
              |
              ○ — ○       (experiment)
```

- `main` просто продолжается
- `experiment` начинается от коммита D и развивается независимо
- Обе существуют одновременно, не влияя друг на друга

В Git ветка — это не более чем имя, указывающее на коммит.
Вот и всё. Никакой копии файлов, никакой дублирующей папки — просто ярлык.

![Ветка как боковой путь от временной шкалы](images/branch_zijtak.png)

## 3. Слияние (merge): объединение двух веток

Когда эксперимент завершён, вы хотите вернуть его в `main`.
Это называется **merge** (слияние).

```
○ — ○ — ○ — ○ — ○ — ○   (main, после слияния)
              |       |
              ○ — ○ ——   (experiment, слит)
```

Git смотрит на общего предка (коммит D) и на оба конца.
Он объединяет изменения и создаёт новый **коммит слияния** (последний ○ на main).

Если одни и те же строки были изменены в обеих ветках → конфликт.
Если нет → автоматическое слияние.

![Слияние двух веток](images/merge_visueel.png)

## 4. HEAD: вы здесь

`HEAD` — это стикер, показывающий, где вы сейчас находитесь в графе.

```
○ — ○ — ○ — ○ — ○
                 ↑
                HEAD (main)
```

Когда вы переключаетесь на другую ветку (`git switch experiment`), стикер перемещается вместе с вами:

```
○ — ○ — ○ — ○ — ○       (main)
              |
              ○ — ○
                   ↑
                  HEAD (experiment)
```

Всё, что вы сейчас закоммитите, попадёт в ту ветку, на которой находится HEAD.

---

## 5. Назад во времени

Допустим, коммит C содержал ошибку, которую вы теперь хотите изучить.
Вы можете временно переместить HEAD на C (`git checkout C`).

```
○ — ○ — ○ — ○ — ○
         ↑
        HEAD (detached)
```

Ваши файлы тогда будут выглядеть точно так, как они выглядели в тот момент.
Git называет это «отсоединённый HEAD» (detached HEAD) — вы находитесь не на ветке, а прямо на коммите.

Полезно для просмотра. Опасно для коммита без создания новой ветки.

## 6. Упражнение: нарисуйте сами

Возьмите ручку и бумагу.

1. Нарисуйте прямую линию с пятью кружками (коммиты от A до E).
2. Нарисуйте ветку, начинающуюся от C, с двумя дополнительными коммитами.
3. Нарисуйте слияние обратно в основную линию после E.
4. Разместите стикер HEAD в правильном месте.

Этот рисунок — именно то, что Git хранит внутри себя.
