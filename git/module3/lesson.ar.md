# الوحدة 3 — التحكم بالإصدارات، بصريًا

قبل أن تكتب أي أمر، عليك أن تكون قادرًا على *رؤيته*.
في هذه الوحدة نبني النموذج الذهني: كيف يبدو Git إذا رسمته؟

---

## 1. الخط الزمني: الالتزامات في صف واحد

أبسط حالة في Git هي خط مستقيم من الالتزامات (commits).
كل commit هو لقطة زمنية. وكل commit يشير إلى الذي قبله.

```
○ — ○ — ○ — ○ — ○
A   B   C   D   E
```

- **A** هو أول commit (نقطة البداية)
- **E** هو آخر commit (الحالة الحالية)
- الأسهم تشير إلى الماضي

اقرأ الخط الزمني من اليسار إلى اليمين: هكذا نما التاريخ.

![الخط الزمني لـ Git — التزامات في صف](images/tijdlijn_lineair.png)

---

## 2. الفرع (branch): مسار جانبي

تخيّل أنك تريد تجربة شيء ما دون المساس بالخط الرئيسي.
تُنشئ **فرعًا** — مسارًا جانبيًا يبدأ من commit موجود بالفعل.

```
○ — ○ — ○ — ○ — ○       (main)
              |
              ○ — ○       (experiment)
```

- `main` يستمر كما هو
- `experiment` يبدأ من commit D وينمو بشكل مستقل
- يتواجد الاثنان في نفس الوقت، دون أن يؤثر أحدهما على الآخر

الفرع في Git ليس أكثر من اسم يشير إلى commit معيّن.
هذا كل شيء. لا نسخة من الملفات، ولا مجلد مكرر — مجرد تسمية (label).

![فرع كمسار جانبي عن الخط الزمني](images/branch_zijtak.png)

## 3. الدمج (merge): توحيد فرعين

عندما تنتهي التجربة، تريد إعادة دمجها في `main`.
يُسمى هذا **merge** (دمج).

```
○ — ○ — ○ — ○ — ○ — ○   (main، بعد الدمج)
              |       |
              ○ — ○ ——   (experiment، تم دمجه)
```

ينظر Git إلى السلف المشترك (commit D) وإلى الطرفين.
ثم يدمج التغييرات وينشئ **commit دمج** جديدًا (آخر ○ على main).

إذا تم تغيير نفس الأسطر في كلا الفرعين ← يحدث تعارض (conflict).
إذا لم يحدث ذلك ← دمج تلقائي.

## 4. HEAD: أنت هنا

`HEAD` هو ملصق يوضّح أين أنت الآن في الرسم البياني.

```
○ — ○ — ○ — ○ — ○
                 ↑
                HEAD (main)
```

عندما تنتقل إلى فرع آخر (`git switch experiment`)، ينتقل الملصق معك:

```
○ — ○ — ○ — ○ — ○       (main)
              |
              ○ — ○
                   ↑
                  HEAD (experiment)
```

كل ما تقوم بعمل commit له الآن، يذهب إلى الفرع الذي تشير إليه HEAD.

---

## 5. العودة بالزمن

لنفترض أن commit C يحتوي على خطأ تريد التحقيق فيه الآن.
يمكنك نقل HEAD مؤقتًا إلى C (`git checkout C`).

```
○ — ○ — ○ — ○ — ○
         ↑
        HEAD (detached)
```

ستظهر ملفاتك عندئذ كما كانت في تلك اللحظة بالضبط.
يُسمّي Git هذا "detached HEAD" (رأس منفصل) — أنت لست على فرع، بل مباشرة على commit.

مفيد للاستكشاف. لكنه خطر إذا قمت بعمل commit دون إنشاء فرع جديد أولاً.

---

## 6. تمرين: ارسمه بنفسك

خذ قلمًا وورقة.

1. ارسم خطًا مستقيمًا بخمس دوائر (commits من A إلى E).
2. ارسم فرعًا يبدأ من C، مع commitين إضافيين.
3. ارسم عملية دمج تعود إلى الخط الرئيسي بعد E.
4. ضع ملصق HEAD في المكان الصحيح.

هذا الرسم هو بالضبط ما يحتفظ به Git داخليًا.
في الوحدة التالية، ستُعيد تمثيل هذا باستخدام بطاقات.
