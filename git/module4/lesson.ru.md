# Модуль 4 — Игра в Git

По-настоящему понять Git можно только тогда, когда вы это *почувствуете*.
В этой игре сама группа становится системой контроля версий.
Никакого терминала. Никаких команд. Зато настоящий опыт того, что происходит внутри Git.

---

## Материалы

- Стикеры или карточки (не менее 30 штук)
- Маркеры (не менее 2 цветов)
- Стол или стена в качестве «временной шкалы»
- 1 рулон скотча или малярной ленты для линий
- Участники: от 3 до 8 человек

---

## Роли

| Роль | Задача |
|-----|------|
| **Maintainer (мейнтейнер)** | Управляет веткой `main`. Одобряет слияния. |
| **Developer A (разработчик A)** | Работает в своей ветке. |
| **Developer B (разработчик B)** | Работает в другой ветке (одновременно с A). |
| **Reviewer (ревьюер)** | Проверяет ветки перед слиянием. |

В небольших группах один человек может совмещать несколько ролей.

---

## «Проект»

Проект — это вымышленный текстовый файл: `README.txt`
Начальная версия содержит три строки:

```
Projectnaam: Git Garden
Versie: 1.0
Beschrijving: Een oefenproject.
```

Запишите эту начальную версию на стикере. Это **коммит A** — начало.
Приклейте его слева на временной шкале.

---

## Раунд 1 — Прямая временная шкала

**Цель:** прочувствовать, как коммиты следуют друг за другом.

1. Developer A записывает небольшое изменение на новом стикере.
   Например: `Versie: 1.1`
   Напишите сверху: `Commit B — Developer A — «версия обновлена»`
2. Приклейте коммит B справа от A, соединив стрелкой.
3. Developer A делает ещё одно изменение → коммит C.
4. Developer B делает то же самое → коммиты D, E.

После пяти коммитов у вас получится временная шкала. Обсудите:
- Кто что изменил?
- Можно ли вернуться к коммиту B?

---

## Раунд 2 — Ветвление

**Цель:** прочувствовать, что два человека могут одновременно работать над одним проектом.

1. С помощью скотча проведите две линии от коммита C — одну вверх, другую прямо.
2. Developer A продолжает работать на верхней линии: коммит D (его версия файла).
3. Developer B работает на нижней линии: коммит D' (его версия — другие изменения).
4. Оба пишут свои стикеры и приклеивают их на свою линию.

Теперь у вас есть две ветки. Обсудите:
- Что находится на линии A? Что на линии B?
- Обе ли они действительны? Да. Git отслеживает обе.

---

## Раунд 3 — Слияние

**Цель:** прочувствовать, что такое слияние — и когда оно может пойти не так.

**Сценарий А: без конфликта**
Developer A изменил описание.
Developer B изменил версию.
→ Конфликта нет. Reviewer объединяет оба изменения на новом стикере: **коммит слияния M**.
Приклейте M справа от двух линий, с двумя стрелками, указывающими на него.

**Сценарий Б: конфликт**
Developer A пишет: `Versie: 2.0`
Developer B тоже пишет: `Versie: 1.5`
→ Конфликт! Одна и та же строка, два разных значения.
Reviewer останавливается. Обсудите: кто прав? Что вы выбираете?
Запишите решение на коммите слияния.

Именно это и делает Git: сливает автоматически, когда может, и останавливается, когда не может.

---

## Раунд 4 — Назад во времени

**Цель:** понять, что Git никогда ничего не забывает.

1. Посмотрите на временную шкалу.
2. Maintainer спрашивает: «Как выглядел файл на момент коммита B?»
3. Все смотрят на стикер коммита B — и могут дать ответ.

Именно это делает Git: каждый коммит содержит полное состояние проекта.
Вы всегда можете вернуться назад.

---

## Обсуждение итогов

Обсудите в группе:

1. Какой момент в игре был самым сложным?
2. Когда возник конфликт — и как вы его разрешили?
3. Какое сообщение коммита могло бы быть лучше?
4. Как это соотносится с вашей повседневной работой с файлами?

---

## Связь с настоящим терминалом

После этой игры вы понимаете эти понятия изнутри:

| Что вы делали в игре | Команда Git |
|--------------------------|--------------|
| Написать стикер (зафиксировать изменение) | `git commit -m "..."` |
| Провести новую линию (создать ветку) | `git branch имя` |
| Переключиться на другую линию | `git switch имя` |
| Объединить две линии | `git merge имя` |
| Посмотреть на более ранний стикер | `git log` / `git checkout` |

В следующем модуле вы сделаете именно это — но уже в терминале.
