# 模块4 — Git游戏

只有真正*体验*过，你才能真正理解Git。
在这个游戏中，小组本身就变成了一个版本控制系统。
没有终端，没有命令，但你会真实地体验到Git内部到底发生了什么。

---

## 所需材料

- 便利贴或卡片（至少30张）
- 记号笔（至少2种颜色）
- 一张桌子或一面墙作为"时间线"
- 1卷胶带或美纹纸胶带，用来画线
- 参与人数：3到8人

---

## 角色

| 角色 | 任务 |
|-----|------|
| **Maintainer（维护者）** | 管理`main`分支，批准合并请求 |
| **Developer A（开发者A）** | 在自己的分支上工作 |
| **Developer B（开发者B）** | 在另一个分支上工作（与A同时进行） |
| **Reviewer（审查者）** | 在分支被合并之前对其进行审查 |

小组人数较少时，一个人可以承担多个角色。

---

## "项目"

这个项目是一个虚构的文本文件：`README.txt`
初始版本有三行：

```
Projectnaam: Git Garden
Versie: 1.0
Beschrijving: Een oefenproject.
```

把这个初始版本写在一张便利贴上。这就是**commit A**——起点。
把它贴在时间线的最左边。

---

## 第一轮 — 直线时间线

**目标：** 体验commit是如何一个接一个产生的。

1. Developer A在新的便利贴上写下一个小改动。
   例如：`Versie: 1.1`
   在上方写：`Commit B — Developer A — "更新了版本号"`
2. 把commit B贴在A的右边，用箭头连接。
3. Developer A再做一次改动 → commit C。
4. Developer B也做同样的事 → commit D、E。

五次commit之后，你就有了一条时间线。讨论一下：
- 谁改了什么？
- 你能回到commit B吗？

---

## 第二轮 — 分支（branching）

**目标：** 体验两个人可以同时在同一个项目上工作。

1. 用胶带从commit C画出两条线——一条向上，一条继续向右。
2. Developer A在上面那条线上继续工作：commit D（他自己的文件版本）。
3. Developer B在下面那条线上工作：commit D'（他自己的版本——不同的改动）。
4. 两人各自写好便利贴，贴在自己的那条线上。

现在你们有了两个分支。讨论一下：
- A那条线上写了什么？B那条线上写了什么？
- 它们都是有效的吗？是的。Git会同时记录这两者。

---

## 第三轮 — 合并（merge）

**目标：** 体验什么是合并——以及什么时候会出问题。

**场景A：没有冲突**
Developer A改动了描述部分。
Developer B改动了版本号部分。
→ 没有冲突。Reviewer在一张新便利贴上把两个改动结合起来：**合并提交M**。
把M贴在两条线的右边，用两个箭头指向它。

**场景B：有冲突**
Developer A写道：`Versie: 2.0`
Developer B也写道：`Versie: 1.5`
→ 冲突！同一行，两个不同的值。
Reviewer暂停下来。讨论一下：谁是对的？你们选择哪个？
把这个决定写在合并提交上。

这正是Git所做的事情：能自动合并时就自动合并，不能时就停下来。

---

## 第四轮 — 回到过去

**目标：** 理解Git从不会忘记任何东西。

1. 看一下时间线。
2. Maintainer问："commit B那时候，文件是什么样子的？"
3. 大家看向commit B的那张便利贴——就能给出答案。

Git做的正是这件事：每个commit都包含了项目的完整状态。
你随时都可以回去查看。

---

## 讨论总结

和小组一起讨论：

1. 游戏中最难的时刻是什么？
2. 冲突是什么时候出现的？你们是怎么解决的？
3. 有没有哪条commit信息本可以写得更好？
4. 这和你们平时处理文件的日常工作有什么关系？

---

## 与真实终端的联系

玩过这个游戏之后，你已经从内部理解了这些概念：

| 你在游戏中做的事 | Git命令 |
|--------------------------|--------------|
| 写一张便利贴（记录一次改动） | `git commit -m "..."` |
| 画一条新线（创建一个分支） | `git branch 名称` |
| 切换到另一条线 | `git switch 名称` |
| 合并两条线 | `git merge 名称` |
| 回看之前的便利贴 | `git log` / `git checkout` |
