# الواجب النهائي — سير عمل Git الكامل

لقد اجتزت النظرية، والرسوم التوضيحية، والخطوات العملية.
الآن ستجمع كل ذلك معًا: سير عمل احترافي كامل على مستودع التمرين.

---

## ما ستقوم به

ستمرّ بالخطوات التي يقوم بها المختبِر يوميًا في فريق حقيقي:

```
إنشاء issue
      ↓
إنشاء فرع
      ↓
كتابة ملف اختبار + عمل commit
      ↓
الدفع (push) إلى GitHub
      ↓
فتح طلب سحب (pull request)
      ↓
استلام المراجعة والتعامل معها
      ↓
الدمج (بواسطة المعلم أو زميل)
      ↓
إغلاق الـ issue
```

---

## المهمة

### الخطوة 1 — إنشاء issue

أنشئ issue في مستودع `git-garden-playground`.

السيناريو: اكتشفت أن التعليمات الموجودة في مجلد `handleidingen/` مفقودة للموضوع الذي تعلمته.

اكتب issue يحتوي على:
- عنوان واضح
- وصف لما هو مفقود
- تصنيف: `documentation`
- معلم (milestone): `Git Garden v1.0` (إن وُجد؛ وإلا، اترك هذا فارغًا)

دوّن رقم الـ issue — ستحتاجه لاحقًا.

---

### الخطوة 2 — إنشاء فرع

```bash
git switch main
git pull
git switch -c docs/handleiding-[اسمك]
```

استخدم اسم فرع وصفيًا يبدأ بـ `docs/`.

---

### الخطوة 3 — كتابة ملف

أنشئ ملفًا داخل مجلد `handleidingen/`:

**`handleidingen/[اسمك]-samenvatting.md`**

اكتب فيه ملخصًا قصيرًا لما تعلمته في مسار Git التعليمي هذا.
كحد أدنى، اذكر:
- 3 أشياء تفهمها الآن ولم تكن تفهمها من قبل
- أمرًا واحدًا (command) تجده الأكثر فائدة
- موقفًا واحدًا من عملك الخاص كنت ترغب في استخدام Git فيه

---

### الخطوة 4 — عمل commit

```bash
git add handleidingen/[اسمك]-samenvatting.md
git commit -m "إضافة ملخص Git لـ [اسمك] (Closes #[رقم-الـissue])"
```

---

### الخطوة 5 — الدفع (Push)

```bash
git push origin docs/handleiding-[اسمك]
```

---

### الخطوة 6 — فتح طلب سحب (Pull Request)

اذهب إلى GitHub وافتح طلب سحب.

**متطلبات وصف طلب السحب:**
- ماذا أضفت؟
- لماذا هذا مفيد للآخرين؟
- الإشارة إلى الـ issue: `Closes #[الرقم]`
- نقطة واحدة يجب على المراجِع التحقق منها تحديدًا

---

### الخطوة 7 — التعامل مع المراجعة

سيقوم معلمك أو أحد زملائك بمراجعة طلب السحب الخاص بك.
إذا كانت هناك ملاحظات:
1. عدّل الملف على فرعك المحلي
2. اعمل commit للتعديل برسالة واضحة
3. ادفع (push) التعديل — سيتم تحديث طلب السحب تلقائيًا

---

### الخطوة 8 — الدمج

بعد الموافقة، يتم دمج طلب السحب من قِبَل المعلم أو من قِبَلك أنت (إن كانت الصلاحيات تسمح بذلك).

بعد ذلك، تحقق من التالي:
```bash
git switch main
git pull
ls handleidingen/
```

أصبح ملفك الآن موجودًا في `main`. إنه جزء من المستودع الرسمي.

---

## معايير التقييم

| العنصر | جيد |
|-----------|------|
| Issue | عنوان واضح، وصف، تصنيف صحيح |
| اسم الفرع | وصفي، يبدأ بـ `docs/` |
| رسالة الـ commit | وصفية، تشير إلى رقم الـ issue |
| الملف | يستوفي المتطلبات، نص خاص بك |
| وصف الـ PR | كامل، يتضمن Closes #الرقم |
| التعامل مع الملاحظات | commit جديد برسالة واضحة |

---

## هل انتهيت؟

إذا تم دمج كل شيء، فقد أثبتّ أنك قادر على:
- تنفيذ سير عمل Git كامل بشكل مستقل
- التواصل باحترافية في الـ issues وطلبات السحب
- معرفة كيفية التعامل مع الملاحظات دون تعطيل سير العمل

هذه ليست حيلة بأربعة أوامر — هذا هو العمل كمحترف.
