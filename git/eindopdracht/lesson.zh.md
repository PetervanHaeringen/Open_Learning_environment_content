# 结业作业 — 完整的Git工作流程

你已经学完了理论知识、可视化演示，以及实际操作步骤。
现在，你要把这一切整合起来：在练习仓库上完成一次完整、专业的工作流程。

---

## 你将要做的事

你会走一遍测试人员在真实团队中每天要经历的步骤：

```
创建一个issue
      ↓
创建一个分支
      ↓
编写测试文件 + 提交
      ↓
推送到GitHub
      ↓
发起拉取请求
      ↓
接收并处理审查意见
      ↓
合并（由老师或同伴完成）
      ↓
关闭issue
```

---

## 作业内容

### 第1步 — 创建一个issue

在 `git-garden-playground` 仓库中创建一个issue。

场景设定：你发现，在`handleidingen/`文件夹中，缺少你所学主题的说明文档。

写一个issue，包含：
- 一个清晰的标题
- 对缺失内容的描述
- 标签：`documentation`
- 里程碑：`Git Garden v1.0`（如果存在的话；如果不存在，就留空）

记下这个issue的编号——之后会用到。

---

### 第2步 — 创建一个分支

```bash
git switch main
git pull
git switch -c docs/handleiding-[你的名字]
```

使用一个具有描述性的分支名，并以 `docs/` 开头。

---

### 第3步 — 编写文件

在 `handleidingen/` 文件夹中创建一个文件：

**`handleidingen/[你的名字]-samenvatting.md`**

在文件中，写一份简短的总结，说明你在这条Git学习路径中学到了什么。
至少要包括：
- 3件你现在理解了、但之前不理解的事情
- 1个你觉得最有用的命令
- 1个你在自己的工作中会想用到Git的情境

---

### 第4步 — 提交

```bash
git add handleidingen/[你的名字]-samenvatting.md
git commit -m "为[你的名字]添加Git总结 (Closes #[issue编号])"
```

---

### 第5步 — 推送

```bash
git push origin docs/handleiding-[你的名字]
```

---

### 第6步 — 发起拉取请求

前往GitHub，发起一个拉取请求。

**PR描述的要求：**
- 你添加了什么？
- 为什么这对其他人有用？
- 引用相关issue：`Closes #[编号]`
- 一个审查者应该特别检查的点

---

### 第7步 — 处理审查意见

你的老师或同学会审查你的PR。
如果有反馈意见：
1. 在本地分支上修改文件
2. 用一条清晰的信息提交这次修改
3. 推送这次修改——PR会自动更新

---

### 第8步 — 合并

获得批准后，PR会由老师或你自己（如果权限允许）进行合并。

之后，检查一下：
```bash
git switch main
git pull
ls handleidingen/
```

你的文件现在已经在`main`中了。它已经成为官方仓库的一部分。

---

## 评分标准

| 项目 | 良好标准 |
|-----------|------|
| Issue | 标题清晰，描述完整，标签正确 |
| 分支名称 | 具有描述性，以`docs/`开头 |
| Commit信息 | 描述清晰，引用了issue编号 |
| 文件 | 符合要求，内容是自己写的 |
| PR描述 | 完整，包含Closes #编号 |
| 处理反馈 | 有新的commit，信息清晰 |

---

## 完成了吗？

如果一切都已经合并完成，说明你已经证明了自己能够：
- 独立完成一次完整的Git工作流程
- 在issue和拉取请求中进行专业的沟通
- 知道如何在不打乱工作流程的情况下处理反馈

这不是一套只有四个命令的小技巧——这是像专业人士一样工作。
