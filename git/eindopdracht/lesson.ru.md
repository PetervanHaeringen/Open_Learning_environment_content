# Итоговое задание — Полный рабочий процесс Git

Вы прошли через теорию, визуализации и практические шаги.
Теперь вы соберёте всё воедино: полный профессиональный рабочий процесс на учебном репозитории.

---

## Что вы будете делать

Вы пройдёте через шаги, которые тестировщик выполняет ежедневно в реальной команде:

```
Создать issue
      ↓
Создать ветку
      ↓
Написать тестовый файл + коммит
      ↓
Push на GitHub
      ↓
Открыть пул-реквест
      ↓
Получить и обработать ревью
      ↓
Merge (преподавателем или сокурсником)
      ↓
Закрыть issue
```

---

## Задание

### Шаг 1 — Создание issue

Создайте issue в репозитории `git-garden-playground`.

Сценарий: вы обнаружили, что в папке `handleidingen/` отсутствуют инструкции по теме, которую вы изучили.

Напишите issue с:
- понятным заголовком
- описанием того, чего не хватает
- меткой: `documentation`
- вехой: `Git Garden v1.0` (если она существует, иначе оставьте это поле пустым)

Запишите номер issue — он понадобится вам позже.

---

### Шаг 2 — Создание ветки

```bash
git switch main
git pull
git switch -c docs/handleiding-[ваше-имя]
```

Используйте описательное имя ветки, начинающееся с `docs/`.

---

### Шаг 3 — Написание файла

Создайте файл в папке `handleidingen/`:

**`handleidingen/[ваше-имя]-samenvatting.md`**

Напишите в нём краткое резюме того, что вы узнали в этом учебном курсе по Git.
Как минимум:
- 3 вещи, которые вы теперь понимаете, а раньше не понимали
- 1 команду, которую вы считаете наиболее полезной
- 1 ситуацию из вашей собственной работы, где вы хотели бы использовать Git

---

### Шаг 4 — Коммит

```bash
git add handleidingen/[ваше-имя]-samenvatting.md
git commit -m "Добавлено резюме по Git для [ваше имя] (Closes #[номер-issue])"
```

---

### Шаг 5 — Push

```bash
git push origin docs/handleiding-[ваше-имя]
```

---

### Шаг 6 — Открытие пул-реквеста

Перейдите на GitHub и откройте пул-реквест.

**Требования к описанию PR:**
- Что вы добавили?
- Почему это полезно для других?
- Ссылка на issue: `Closes #[номер]`
- Один момент, который ревьюер должен проверить особо

---

### Шаг 7 — Обработка ревью

Ваш преподаватель или однокурсник проверит ваш PR.
Если будут замечания:
1. Внесите изменения в файл в своей локальной ветке
2. Сделайте коммит изменения с понятным сообщением
3. Отправьте (push) изменение — PR обновится автоматически

---

### Шаг 8 — Merge

После одобрения PR сливается преподавателем или вами самими (если права это позволяют).

После этого проверьте:
```bash
git switch main
git pull
ls handleidingen/
```

Ваш файл теперь находится в `main`. Он стал частью официального репозитория.

---

## Критерии оценки

| Компонент | Хорошо |
|-----------|------|
| Issue | Понятный заголовок, описание, правильная метка |
| Имя ветки | Описательное, начинается с `docs/` |
| Сообщение коммита | Описательное, ссылается на номер issue |
| Файл | Соответствует требованиям, собственный текст |
| Описание PR | Полное, включает Closes #номер |
| Обработка отзывов | Новый коммит с понятным сообщением |

---

## Готово?

Если всё было слито, вы доказали, что умеете:
- самостоятельно проводить полный рабочий процесс Git
- профессионально общаться в issue и пул-реквестах
- знать, как обрабатывать отзывы, не нарушая рабочий процесс

Это не трюк из четырёх команд — это работа как у профессионала.
