# 最終課題 — Gitの完全なワークフロー

理論、可視化、そして実践的な手順を、すべて経験してきました。
ここからは、それらを一つにまとめます：練習用リポジトリで、プロフェッショナルなワークフローを最初から最後まで実行します。

---

## これから行うこと

実際のチームでテスターが日常的に行う手順を、一通り経験します：

```
イシューを作成する
      ↓
ブランチを作成する
      ↓
テストファイルを書く + コミットする
      ↓
GitHubにプッシュする
      ↓
プルリクエストを開く
      ↓
レビューを受け取り、対応する
      ↓
マージする（講師またはピアによる）
      ↓
イシューをクローズする
```

---

## 課題内容

### ステップ1 — イシューを作成する

`git-garden-playground` リポジトリにイシューを作成します。

シナリオ：あなたが学んだテーマについて、`handleidingen/` フォルダに説明が不足していることに気づいた、という設定です。

次の内容を含むイシューを書きます：
- わかりやすいタイトル
- 何が不足しているかの説明
- ラベル：`documentation`
- マイルストーン：`Git Garden v1.0`（存在する場合。存在しなければ、この項目は空欄で構いません）

イシュー番号をメモしておいてください——あとで必要になります。

---

### ステップ2 — ブランチを作成する

```bash
git switch main
git pull
git switch -c docs/handleiding-[あなたの名前]
```

`docs/` で始まる、わかりやすいブランチ名を使ってください。

---

### ステップ3 — ファイルを書く

`handleidingen/` フォルダの中にファイルを作成します：

**`handleidingen/[あなたの名前]-samenvatting.md`**

その中に、このGit学習パスで学んだことについて、簡単なまとめを書いてください。
最低限、次の内容を含めてください：
- 以前はわからなかったが、今は理解できるようになったこと3つ
- あなたが最も役立つと感じたコマンド1つ
- 自分の実際の仕事の中で、Gitを使いたいと思う場面1つ

---

### ステップ4 — コミットする

```bash
git add handleidingen/[あなたの名前]-samenvatting.md
git commit -m "[あなたの名前]によるGitのまとめを追加 (Closes #[イシュー番号])"
```

---

### ステップ5 — プッシュする

```bash
git push origin docs/handleiding-[あなたの名前]
```

---

### ステップ6 — プルリクエストを開く

GitHubに移動し、プルリクエストを開きます。

**PRの説明に必要な内容：**
- 何を追加したか？
- それが他の人にとってなぜ役立つのか？
- イシューへの参照：`Closes #[番号]`
- レビュアーが特に確認すべき点を1つ

---

### ステップ7 — レビューに対応する

講師またはクラスメートが、あなたのPRをレビューします。
フィードバックがあった場合：
1. 自分のローカルブランチでファイルを修正する
2. わかりやすいメッセージをつけて、その修正をコミットする
3. その変更をプッシュする——PRは自動的に更新されます

---

### ステップ8 — マージする

承認された後、講師、またはあなた自身（権限が許す場合）によってPRがマージされます。

その後、次を確認してください：
```bash
git switch main
git pull
ls handleidingen/
```

あなたのファイルは、今や`main`の中にあります。それは、正式なリポジトリの一部になったということです。

---

## 評価基準

| 項目 | 良い状態 |
|-----------|------|
| イシュー | タイトルが明確、説明があり、正しいラベル |
| ブランチ名 | わかりやすく、`docs/` で始まっている |
| コミットメッセージ | わかりやすく、イシュー番号を参照している |
| ファイル | 要件を満たしており、自分自身の文章である |
| PRの説明 | 内容が完全で、Closes #番号が含まれている |
| フィードバックへの対応 | わかりやすいメッセージをつけた新しいコミット |

---

## 完了しましたか？

すべてがマージされたなら、あなたは次のことを証明したことになります：
- Gitの完全なワークフローを、自分の力で実行できること
- イシューやプルリクエストの中で、プロフェッショナルなコミュニケーションができること
- ワークフローを乱すことなく、フィードバックにどう対応すればよいかを理解していること

これは、4つのコマンドだけの小手先の技ではありません——これは、プロフェッショナルとして働くということです。
