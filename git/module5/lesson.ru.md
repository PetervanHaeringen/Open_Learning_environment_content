# Модуль 5 — Работа локально

Вы увидели Git, почувствовали его и нарисовали.
Теперь вы будете делать это сами. В терминале, на настоящем репозитории.

---

## Подготовка: установка и настройка

**Установите Git**
- Windows: [git-scm.com/download/win](https://git-scm.com/download/win)
- Mac: откройте терминал, введите `git --version` (установится автоматически или появится инструкция)
- Linux: `sudo apt install git`

**Настройте своё имя и email** (они появляются в каждом коммите, который вы делаете):

```bash
git config --global user.name "Ваше имя"
git config --global user.email "ваш@email.com"
```

Проверьте настройки:

```bash
git config --list
```

## Учебный репозиторий

Для этого учебного курса мы используем отдельный учебный репозиторий:

**`git-garden-playground`**

Точный адрес (URL) вам даст преподаватель.
Он начинается с `https://github.com/...`

Этот репозиторий предназначен специально для практики — здесь ничего нельзя сломать.

---

## Шаг 1: Клонирование

Клонирование — это скачивание репозитория на свой компьютер.

```bash
git clone https://github.com/...url.../git-garden-playground
```

После клонирования:

```bash
cd git-garden-playground
ls
```

Вы увидите файлы репозитория. А ещё есть скрытая папка `.git` — машина времени.

---

## Шаг 2: Просмотр статуса

`git status` — ваш компас. Используйте его часто.

```bash
git status
```

Вы увидите, на какой ветке находитесь и есть ли изменённые файлы.

---

## Шаг 3: Внесение изменения

Откройте папку в своём редакторе (или используйте терминал).
Создайте новый файл в папке `deelnemers/`:

```bash
mkdir -p deelnemers
echo "Naam: [ваше имя]" > deelnemers/[ваше-имя].txt
```

Затем проверьте статус:

```bash
git status
```

Git сообщит, что новый файл «неотслеживаемый» (untracked) — он существует, но Git пока его не отслеживает.

---

## Шаг 4: Индексация (staging)

Индексация означает: «я хочу включить этот файл в следующий коммит».

```bash
git add deelnemers/[ваше-имя].txt
```

Или добавьте всё сразу:

```bash
git add .
```

Снова проверьте статус. Теперь файл находится в «индексе» (staging area) — готов к коммиту.

---

## Шаг 5: Коммит

Теперь вы создаёте снимок.

```bash
git commit -m "Добавить [ваше имя] в список участников"
```

Хорошее сообщение коммита:
- начинается с глагола: «Добавить», «Исправить», «Обновить», «Удалить»
- описывает *что* изменилось, а не *как*
- короткое (максимум ~72 символа)

---

## Шаг 6: Просмотр истории

```bash
git log
```

Вы увидите все коммиты: хеш, автора, дату, сообщение.

Для компактного обзора:

```bash
git log --oneline
```

Для наглядного обзора с ветками:

```bash
git log --oneline --graph --all
```

---

## Шаг 7: Просмотр различий

Хотите увидеть, что изменилось, перед коммитом?

```bash
git diff
```

После индексации, но перед коммитом:

```bash
git diff --staged
```

---

## Итог: ежедневный рабочий процесс

```
[внести изменение]
      ↓
git add .
      ↓
git commit -m "..."
      ↓
git push   (рассмотрим в модуле 6)
```

Повторяйте этот шаблон десятки раз в день.
Со временем это станет само собой разумеющимся.
