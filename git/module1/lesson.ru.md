# Модуль 1 — Происхождение и философия

Сегодня Git — самая широко используемая система контроля версий в мире.
Но она существовала не всегда. И появилась не случайно — за этим стояла серьёзная проблема.

---

## 1. Проблема: разработка программного обеспечения в команде

Представь, что ты работаешь над одним проектом с десятью людьми.
У всех одни и те же файлы. Все вносят изменения.

Как тогда узнать:
- кто что изменил?
- когда закралась ошибка?
- как вернуться к вчерашнему состоянию?

Без контроля версий ответ один: ты не знаешь.
Ты отправляешь файлы по электронной почте, переписываешь работу друг друга, теряешь код.

Именно это раньше и происходило в командах разработчиков.

---

## 2. Централизованный контроль версий: предыдущее поколение

До Git существовали системы вроде SVN и CVS.
Они работали **централизованно**: всю историю хранил один центральный сервер.

У этого были недостатки:
- сервер выходит из строя → все простаивают
- нельзя работать без сетевого подключения
- одна ошибка на сервере = всё потеряно

## 3. Линус Торвальдс и конфликт 2005 года

Линус Торвальдс — создатель ядра Linux, сердца многих операционных систем.
Над ним работали тысячи разработчиков.

Они использовали коммерческую систему **BitKeeper**.
Бесплатную для проектов с открытым исходным кодом — пока в 2005 году лицензию не отозвали.

У Линуса был выбор: перейти на существующую систему или создать что-то своё.
Ни один из существующих инструментов не делал того, что ему было нужно.

За **две недели** он написал основу Git.

> "I'm an egotistical bastard, and I name all my projects after myself.
> First Linux, now Git."
> — Linus Torvalds

## 4. Философия Git

Git построен на трёх ключевых идеях:

**Распределённость**
У каждого есть полная история на собственном компьютере.
Можно работать без интернета. Сервер не священен.

**Безопасность**
Каждый commit получает уникальный код (hash), основанный на содержимом.
Любое изменение в истории сразу заметно.

**Скорость**
Git работает локально. Почти всё происходит на твоей собственной машине.
Никакого ожидания, никакой зависимости от сервера.

---

## 5. Git — это не GitHub

Это распространённое заблуждение.

**Git** — это система контроля версий, программа, которую ты устанавливаешь локально.
**GitHub** — это сайт, где можно хранить и делиться проектами Git.

Git изобрёл Линус Торвальдс.
GitHub — это компания, основанная в 2008 году и купленная Microsoft в 2018 году.

Можно использовать Git без GitHub.
Но GitHub без Git не имеет смысла.

---

## 6. Почему это важно для тебя как тестировщика?

Как тестировщик ты работаешь с кодом, тестовыми скриптами, отчётами об ошибках и документацией.
Все эти файлы со временем меняются.

Git даёт тебе:
- полную историю каждого файла
- понимание того, кто что и когда изменил
- возможность вернуться назад, когда что-то идёт не так
- совместную работу без хаоса

Чтобы Git был тебе полезен, не нужно уметь программировать.
