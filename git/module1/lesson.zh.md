# 第 1 单元 — 起源与理念

Git 如今是世界上使用最广泛的版本控制系统。
但它并非一直存在。它的诞生也不是偶然的——背后有一个严肃的问题。

---

## 1. 问题：团队协作开发软件

设想你和十个人一起开发同一个项目。
每个人都有相同的文件。每个人都在做修改。

那么你怎么知道：
- 谁改了什么？
- 错误是什么时候混进来的？
- 怎样回到昨天的状态？

如果没有版本控制，答案就是：你不知道。
你通过电子邮件发送文件，覆盖彼此的工作，丢失代码。

这正是过去软件团队里发生的情况。

---

## 2. 集中式版本控制：上一代

在 Git 之前，有像 SVN 和 CVS 这样的系统。
它们以**集中式**方式工作：由一台中央服务器保存全部历史记录。

这带来了一些缺点：
- 服务器宕机 → 所有人都停摆
- 没有网络连接就无法工作
- 服务器上的一个错误 = 一切尽失

## 3. Linus Torvalds 与 2005 年的冲突

Linus Torvalds 是 Linux 内核的创造者——许多操作系统的核心。
成千上万的开发者参与其中。

他们使用了一个商业系统：**BitKeeper**。
它对开源项目免费——直到 2005 年许可被撤销。

Linus 面临一个选择：转用现有系统，或者自己动手做一个。
现有的工具没有一个能满足他的需求。

在**两周**内，他写出了 Git 的基础。

> "I'm an egotistical bastard, and I name all my projects after myself.
> First Linux, now Git."
> — Linus Torvalds

## 4. Git 的理念

Git 建立在三个核心理念之上：

**分布式**
每个人的电脑上都拥有完整的历史记录。
你可以离线工作。服务器不是神圣的。

**安全**
每个 commit 都会得到一个基于内容的唯一编码（hash）。
对历史记录的任何改动都会立即被察觉。

**快速**
Git 在本地运行。几乎所有操作都在你自己的机器上完成。
没有等待时间，也不依赖服务器。

---

## 5. Git 不是 GitHub

这是一个常见的混淆。

**Git** 是版本控制系统——一个你在本地安装的程序。
**GitHub** 是一个网站，你可以在上面存储和分享 Git 项目。

Git 由 Linus Torvalds 发明。
GitHub 是一家公司，成立于 2008 年，2018 年被 Microsoft 收购。

你可以在不使用 GitHub 的情况下使用 Git。
但没有 Git 的 GitHub 毫无意义。

---

## 6. 作为测试员，这为什么与你相关？

作为测试员，你要处理代码、测试脚本、缺陷报告和文档。
所有这些文件都会随时间变化。

Git 给你带来：
- 每个文件的完整历史记录
- 了解谁在何时改了什么
- 在出错时可以回退的能力
- 没有混乱的协作

你不需要会编程，也能发现 Git 的用处。
