# 모듈 1 — 기원과 철학

Git은 오늘날 세계에서 가장 널리 사용되는 버전 관리 시스템입니다.
하지만 항상 존재했던 것은 아닙니다. 그리고 우연이 아니라 심각한 문제 뒤에 탄생했습니다.

---

## 1. 문제: 팀으로 소프트웨어 만들기

열 명이 같은 프로젝트를 한다고 상상해 보세요.
모두가 같은 파일을 가지고 있습니다. 모두가 변경을 합니다.

그럼 어떻게 알 수 있을까요:
- 누가 무엇을 변경했는지?
- 언제 오류가 들어왔는지?
- 어제 상태로 어떻게 돌아가는지?

버전 관리가 없으면 답은 간단합니다: 모릅니다.
이메일로 파일을 보내고, 서로의 작업을 덮어쓰고, 코드를 잃어버립니다.

이것이 바로 과거 소프트웨어 팀에서 실제로 일어났던 일입니다.

---

## 2. 중앙 집중식 버전 관리: 이전 세대

Git 이전에는 SVN이나 CVS 같은 시스템이 있었습니다.
이들은 **중앙 집중식**으로 작동했습니다: 하나의 중앙 서버가 모든 기록을 보관했습니다.

이것에는 단점이 있었습니다:
- 서버가 다운되면 → 모두 멈춥니다
- 네트워크 연결 없이는 작업할 수 없습니다
- 서버의 한 오류 = 모든 것이 사라집니다

## 3. 리누스 토르발스와 2005년의 갈등

리누스 토르발스는 리눅스 커널의 창시자입니다 — 많은 운영 체제의 심장입니다.
수천 명의 개발자가 이에 참여했습니다.

그들은 상용 시스템인 **BitKeeper**를 사용했습니다.
오픈 소스 프로젝트에는 무료였습니다 — 2005년에 라이선스가 철회될 때까지.

리누스에게 선택지가 있었습니다: 기존 시스템으로 전환하거나, 직접 무언가를 만들거나.
기존 도구 중 그가 필요로 하는 것을 해주는 것은 없었습니다.

**두 주** 만에 그는 Git의 기초를 작성했습니다.

> "나는 이기적인 놈이다. 모든 프로젝트에 내 이름을 붙인다.
> 처음에는 리눅스, 이제는 Git이다."
> — 리누스 토르발스

## 4. Git의 철학

Git은 세 가지 핵심 아이디어 위에 세워졌습니다:

**분산형**
모두가 자신의 컴퓨터에 전체 기록을 가지고 있습니다.
인터넷 없이도 작업할 수 있습니다. 서버는 신성하지 않습니다.

**안전**
모든 커밋은 내용을 기반으로 한 고유 코드(해시)를 받습니다.
기록에서 무언가를 변경하면 즉시 알 수 있습니다.

**빠름**
Git은 로컬에서 작동합니다. 거의 모든 것이 자신의 기계에서 일어납니다.
대기 시간도 없고, 서버에 의존하지도 않습니다.

---

## 5. Git은 GitHub이 아닙니다

이것은 흔한 혼동입니다.

**Git**은 버전 관리 시스템입니다 — 로컬에 설치하는 프로그램입니다.
**GitHub**은 Git 프로젝트를 저장하고 공유할 수 있는 웹사이트입니다.

Git은 리누스 토르발스가 발명했습니다.
GitHub은 2008년에 설립되어 2018년에 Microsoft가 인수한 회사입니다.

GitHub 없이도 Git을 사용할 수 있습니다.
하지만 Git 없는 GitHub은 의미가 없습니다.

---

## 6. 테스터인 당신에게 왜 이것이 관련이 있을까요?

테스터로서 당신은 코드, 테스트 스크립트, 버그 보고서, 문서와 함께 작업합니다.
이 모든 파일은 시간이 지남에 따라 변경됩니다.

Git은 당신에게 다음을 제공합니다:
- 모든 파일의 완전한 기록
- 누가 언제 무엇을 변경했는지에 대한 통찰
- 무언가 잘못되었을 때 되돌아갈 수 있는 능력
- 혼란 없는 협업

Git이 유용하려면 프로그래밍을 할 줄 알 필요는 없습니다.
