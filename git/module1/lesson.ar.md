# الوحدة 1 — الأصل والفلسفة

يُعد Git اليوم أكثر أنظمة التحكم في الإصدارات استخدامًا في العالم.
لكنه لم يكن موجودًا دائمًا. ولم ينشأ مصادفةً — كان وراءه مشكلة جدية.

---

## 1. المشكلة: تطوير البرمجيات ضمن فريق

تخيّل أنك تعمل مع عشرة أشخاص على المشروع نفسه.
الجميع لديهم الملفات نفسها. والجميع يُجري تعديلات.

كيف تعرف عندئذٍ:
- مَن غيّر ماذا؟
- متى تسلّل خطأ إلى العمل؟
- كيف تعود إلى حالة الأمس؟

من دون نظام للتحكم في الإصدارات، يكون الجواب: لا تعرف.
ترسل الملفات عبر البريد الإلكتروني، وتطمس عمل بعضكم البعض، وتفقد الشيفرة.

هذا بالضبط ما كان يحدث سابقًا في فرق تطوير البرمجيات.

---

## 2. التحكم المركزي في الإصدارات: الجيل السابق

قبل Git كانت هناك أنظمة مثل SVN وCVS.
كانت تعمل بشكل **مركزي**: خادم مركزي واحد يحفظ كل التاريخ.

كان لذلك مساوئ:
- يتعطّل الخادم ← يتوقف الجميع عن العمل
- لا يمكنك العمل من دون اتصال بالشبكة
- خطأ واحد على الخادم = ضياع كل شيء

## 3. لينوس تورفالدس ونزاع عام 2005

لينوس تورفالدس هو صانع نواة Linux — قلب العديد من أنظمة التشغيل.
عمل عليها آلاف المطوّرين.

كانوا يستخدمون نظامًا تجاريًا: **BitKeeper**.
كان مجانيًا لمشاريع المصدر المفتوح — إلى أن سُحب الترخيص في عام 2005.

كان أمام لينوس خيار: الانتقال إلى نظام موجود، أو بناء شيء بنفسه.
لم يكن أيٌّ من الأدوات الموجودة يفعل ما كان يحتاجه.

في **أسبوعين** كتب أساس Git.

> "I'm an egotistical bastard, and I name all my projects after myself.
> First Linux, now Git."
> — Linus Torvalds

## 4. فلسفة Git

بُني Git على ثلاث أفكار جوهرية:

**موزّع**
كل شخص لديه التاريخ الكامل على حاسوبه الخاص.
يمكنك العمل من دون إنترنت. الخادم ليس مقدّسًا.

**آمن**
كل commit يحصل على رمز فريد (hash) مبني على المحتوى.
أي تغيير في التاريخ يُكتشف فورًا.

**سريع**
يعمل Git محليًا. كل شيء تقريبًا يجري على جهازك.
لا وقت انتظار، ولا اعتماد على خادم.

---

## 5. Git ليس GitHub

هذا خلط شائع.

**Git** هو نظام التحكم في الإصدارات — برنامج تُثبّته محليًا.
**GitHub** هو موقع إلكتروني يمكنك فيه تخزين مشاريع Git ومشاركتها.

اخترع Git لينوس تورفالدس.
أما GitHub فهي شركة تأسست عام 2008، واشترتها Microsoft عام 2018.

يمكنك استخدام Git من دون GitHub.
لكن GitHub من دون Git لا معنى له.

---

## 6. لماذا يهمّك هذا كمختبِر (tester)؟

بصفتك مختبِرًا، تعمل مع الشيفرة وسكربتات الاختبار وتقارير الأخطاء والتوثيق.
كل هذه الملفات تتغيّر مع الوقت.

يمنحك Git:
- تاريخًا كاملًا لكل ملف
- معرفة مَن غيّر ماذا ومتى
- إمكانية العودة إلى الوراء عند حدوث خطأ
- التعاون من دون فوضى

لست بحاجة إلى البرمجة كي تجد Git مفيدًا.
