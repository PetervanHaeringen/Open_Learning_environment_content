# Модуль 6 — Ветки и совместная работа

Вы уже знаете базовый рабочий процесс. Теперь вы добавляете совместную работу.
Совместная работа в Git строится вокруг веток (branches) и пул-реквестов (pull requests) — двух инструментов, которые позволяют командам работать над одним проектом одновременно, без хаоса.

---

## 1. Создание ветки

Всегда создавайте ветку для новой задачи.
Никогда не работайте напрямую в `main`.

```bash
git branch моя-ветка
git switch моя-ветка
```

Или за один шаг:

```bash
git switch -c моя-ветка
```

Проверьте, в какой ветке вы находитесь:

```bash
git branch
```

Ветка со звёздочкой `*` перед ней — текущая.

Хорошие имена веток описательны и коротки:
- `add-readme`
- `fix-intro-typo`
- `update-version-number`

---

## 2. Коммит изменений в ветке

Работайте так же, как в модуле 5:

```bash
# внесите изменение в файл
git add .
git commit -m "Описание изменения"
```

Теперь ваши коммиты находятся в вашей ветке — а не в `main`.
`main` остаётся без изменений.

---

## 3. Отправка (push) на GitHub

Теперь вы отправляете свою ветку на GitHub:

```bash
git push origin моя-ветка
```

В первый раз Git попросит подтвердить вашу учётную запись GitHub.
После push ветка появится на GitHub — видимая для остальных.

---

## 4. Открытие пул-реквеста

**Пул-реквест (PR)** — это предложение: «я хочу влить свою ветку в main».

На GitHub:
1. Перейдите в репозиторий `git-garden-playground`
2. Вы увидите жёлтую полосу: «my-branch — Compare & pull request»
3. Нажмите на неё
4. Напишите описание:
   - Что вы изменили?
   - Почему?
   - Есть ли что-то, что ревьюер должен знать?
5. Нажмите **«Create pull request»**

![Создание пул-реквеста на GitHub](images/pull_request_aanmaken.png)

Пул-реквест — это разговор, а не форма.
Чем лучше описание, тем более гладким будет ревью.

---

## 5. Рабочий процесс совместной работы

```
main (стабильная)
 |
 ├── ветка A (Developer A работает здесь)
 |        → коммиты → push → PR → ревью → merge
 |
 ├── ветка B (Developer B работает здесь)
 |        → коммиты → push → PR → ревью → merge
 |
main (обновлена после слияний)
```

Каждый работает в своей собственной ветке.
`main` обновляется только через одобренные пул-реквесты.
Так `main` всегда остаётся стабильной.

---

## 6. Получение чужих изменений

Если чья-то ветка была слита, вы тоже захотите получить эти изменения.

```bash
git switch main
git pull
```

`git pull` загружает самую свежую версию `main` с GitHub.

Хотите узнать, что есть на GitHub, не меняя свои локальные файлы?

```bash
git fetch
git status
```

`git fetch` только получает информацию. `git pull` получает информацию *и* обновляет ваши файлы.

---

## 7. Практическое задание

1. Клонируйте репозиторий `git-garden-playground` (если ещё не сделали этого).
2. Создайте ветку со своим именем: `contribution-[ваше-имя]`
3. Создайте файл в папке `bijdragen/`: `[ваше-имя].md`
4. Напишите в нём:
   - Что вы ожидаете узнать о Git
   - Один вопрос, который у вас ещё остался
5. Сделайте коммит файла с понятным сообщением.
6. Отправьте (push) ветку на GitHub.
7. Откройте пул-реквест с кратким описанием.

После задания: ваш преподаватель или однокурсник проверит PR.
