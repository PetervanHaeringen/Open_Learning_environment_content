# الوحدة 6 — الفروع والتعاون

أنت الآن تعرف سير العمل الأساسي. حان وقت إضافة التعاون.
يدور التعاون في Git حول الفروع (branches) وطلبات السحب (pull requests) — الأداتان اللتان تتيحان للفرق العمل على نفس المشروع في نفس الوقت دون فوضى.

---

## 1. إنشاء فرع

أنشئ دائمًا فرعًا لكل مهمة جديدة.
لا تعمل مباشرة على `main` أبدًا.

```bash
git branch فرعي
git switch فرعي
```

أو في خطوة واحدة:

```bash
git switch -c فرعي
```

تحقق من الفرع الذي أنت عليه:

```bash
git branch
```

الفرع الذي أمامه `*` هو الفرع الحالي.

أسماء الفروع الجيدة تكون وصفية وقصيرة، مثل:
- `add-readme`
- `fix-intro-typo`
- `update-version-number`

---

## 2. عمل commit للتغييرات على الفرع

اعمل تمامًا كما فعلت في الوحدة 5:

```bash
# قم بإجراء تغيير في أحد الملفات
git add .
git commit -m "وصف التغيير"
```

الآن أصبحت التزاماتك (commits) موجودة على فرعك — وليس على `main`.
يبقى `main` دون تغيير.

---

## 3. الدفع (push) إلى GitHub

الآن سترسل فرعك إلى GitHub:

```bash
git push origin فرعي
```

في المرة الأولى، سيطلب منك Git تأكيد حساب GitHub الخاص بك.
بعد الدفع، سيظهر الفرع على GitHub — مرئيًا للآخرين.

---

## 4. فتح طلب سحب (Pull Request)

**طلب السحب (PR)** هو اقتراح: "أريد دمج فرعي مع main."

على GitHub:
1. اذهب إلى مستودع `git-garden-playground`
2. سترى شريطًا أصفر: "my-branch — Compare & pull request"
3. اضغط عليه
4. اكتب وصفًا يوضّح:
   - ماذا غيّرت؟
   - لماذا؟
   - هل هناك ما ينبغي أن يعرفه المراجِع؟
5. اضغط على **"Create pull request"**

![إنشاء طلب سحب على GitHub](images/pull_request_aanmaken.png)

طلب السحب هو محادثة، وليس نموذجًا.
كلما كان الوصف أفضل، كانت المراجعة أكثر سلاسة.

---

## 5. سير عمل التعاون

```
main (مستقر)
 |
 ├── فرع A (يعمل هنا Developer A)
 |        → التزامات (commits) → دفع (push) → طلب سحب (PR) → مراجعة → دمج
 |
 ├── فرع B (يعمل هنا Developer B)
 |        → التزامات (commits) → دفع (push) → طلب سحب (PR) → مراجعة → دمج
 |
main (محدَّث بعد عمليات الدمج)
```

يعمل كل شخص على فرعه الخاص.
لا يتم تحديث `main` إلا من خلال طلبات السحب المعتمَدة.
بهذه الطريقة، يظل `main` مستقرًا دائمًا.

---

## 6. الحصول على تغييرات الآخرين

إذا تم دمج فرع شخص آخر، فستريد الحصول على تلك التغييرات أيضًا.

```bash
git switch main
git pull
```

يقوم `git pull` بجلب أحدث نسخة من `main` من GitHub.

هل تريد معرفة ما هو موجود على GitHub دون تغيير ملفاتك المحلية؟

```bash
git fetch
git status
```

يقوم `git fetch` بجلب المعلومات فقط. أما `git pull` فيجلب المعلومات *ويُحدّث* ملفاتك أيضًا.

---

## 7. تمرين عملي

1. استنسخ (clone) مستودع `git-garden-playground` (إن لم تكن قد فعلت ذلك بعد).
2. أنشئ فرعًا باسمك: `bijdrage-[اسمك]`
3. أنشئ ملفًا داخل مجلد `bijdragen/`: `[اسمك].md`
4. اكتب فيه:
   - ما الذي تتوقع تعلّمه من Git
   - سؤال واحد لا يزال لديك
5. قم بعمل commit للملف برسالة واضحة.
6. ادفع (push) الفرع إلى GitHub.
7. افتح طلب سحب (pull request) مع وصف قصير.

بعد التمرين: سيقوم معلمك أو أحد زملائك بمراجعة طلب السحب.
