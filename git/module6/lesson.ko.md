# 모듈 6 — 브랜치와 협업

기본 워크플로우는 이미 알고 있습니다. 이제 협업을 추가할 차례입니다.
Git에서의 협업은 브랜치와 풀 리퀘스트를 중심으로 이루어집니다 — 이 두 가지 도구 덕분에 팀은 혼란 없이 같은 프로젝트에서 동시에 작업할 수 있습니다.

---

## 1. 브랜치 만들기

새로운 작업을 할 때는 항상 브랜치를 만드세요.
절대로 `main`에서 직접 작업하지 마세요.

```bash
git branch 내-브랜치
git switch 내-브랜치
```

또는 한 번에:

```bash
git switch -c 내-브랜치
```

지금 어떤 브랜치에 있는지 확인하세요:

```bash
git branch
```

앞에 `*`가 붙은 브랜치가 현재 브랜치입니다.

좋은 브랜치 이름은 설명적이면서도 짧습니다:
- `add-readme`
- `fix-intro-typo`
- `update-version-number`

---

## 2. 브랜치에서 변경 사항 커밋하기

모듈 5에서와 똑같이 작업하세요:

```bash
# 파일에 변경 사항 만들기
git add .
git commit -m "변경 사항 설명"
```

이제 당신의 커밋들은 당신의 브랜치에 있습니다 — `main`에 있는 것이 아닙니다.
`main`은 변경되지 않은 상태로 남아 있습니다.

---

## 3. GitHub로 푸시하기

이제 당신의 브랜치를 GitHub로 전송합니다:

```bash
git push origin 내-브랜치
```

처음에는 Git이 당신의 GitHub 계정 확인을 요청합니다.
푸시가 끝나면, 그 브랜치는 GitHub에 존재하게 됩니다 — 다른 사람들도 볼 수 있게 됩니다.

---

## 4. 풀 리퀘스트 열기

**풀 리퀘스트(PR)**는 하나의 제안입니다: "제 브랜치를 main에 병합하고 싶습니다."

GitHub에서:
1. `git-garden-playground` 저장소로 이동합니다
2. 노란색 배너가 보입니다: "my-branch — Compare & pull request"
3. 그것을 클릭합니다
4. 설명을 작성합니다:
   - 무엇을 바꿨나요?
   - 왜 바꿨나요?
   - 리뷰어가 알아야 할 사항이 있나요?
5. **"Create pull request"**를 클릭합니다

![GitHub에서 풀 리퀘스트 만들기](images/pull_request_aanmaken.png)

풀 리퀘스트는 양식이 아니라 대화입니다.
설명이 좋을수록, 리뷰 과정도 더 원활해집니다.

---

## 5. 협업 워크플로우

```
main (안정된 상태)
 |
 ├── 브랜치 A (Developer A가 여기서 작업)
 |        → 커밋 → 푸시 → PR → 리뷰 → 병합
 |
 ├── 브랜치 B (Developer B가 여기서 작업)
 |        → 커밋 → 푸시 → PR → 리뷰 → 병합
 |
main (병합 후 업데이트됨)
```

모든 사람은 자신의 브랜치에서 작업합니다.
`main`은 승인된 풀 리퀘스트를 통해서만 업데이트됩니다.
이렇게 함으로써 `main`은 항상 안정적인 상태를 유지합니다.

---

## 6. 다른 사람의 변경 사항 가져오기

누군가의 브랜치가 병합되었다면, 당신도 그 변경 사항을 가져오고 싶을 것입니다.

```bash
git switch main
git pull
```

`git pull`은 GitHub에서 최신 버전의 `main`을 가져옵니다.

로컬 파일을 바꾸지 않고 GitHub에 무엇이 있는지 알고 싶다면?

```bash
git fetch
git status
```

`git fetch`는 정보만 가져옵니다. `git pull`은 정보를 가져오면서 *동시에* 당신의 파일도 업데이트합니다.

---

## 7. 실습 과제

1. `git-garden-playground` 저장소를 클론하세요 (아직 하지 않았다면).
2. 자신의 이름으로 브랜치를 만드세요: `bijdrage-[당신의-이름]`
3. `bijdragen/` 폴더 안에 파일을 만드세요: `[당신의-이름].md`
4. 그 안에 다음을 적으세요:
   - Git에서 무엇을 배우고 싶은지
   - 아직 남아 있는 질문 하나
5. 명확한 메시지와 함께 파일을 커밋하세요.
6. 그 브랜치를 GitHub로 푸시하세요.
7. 짧은 설명과 함께 풀 리퀘스트를 여세요.

과제를 마친 후에는: 선생님이나 동료 학생이 그 PR을 리뷰할 것입니다.
