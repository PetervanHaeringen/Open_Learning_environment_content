# モジュール6 — ブランチと共同作業

基本のワークフローはもう身につきました。次は共同作業を加えていきます。
Gitでの共同作業は、ブランチとプルリクエストを中心に成り立っています——この2つの仕組みによって、チームは同じプロジェクトに同時に取り組んでも、混乱に陥ることがありません。

---

## 1. ブランチを作成する

新しいタスクには、必ずブランチを作りましょう。
`main`で直接作業することは絶対にしません。

```bash
git branch 自分のブランチ
git switch 自分のブランチ
```

または、1つのコマンドでまとめて：

```bash
git switch -c 自分のブランチ
```

今どのブランチにいるか確認します：

```bash
git branch
```

先頭に`*`が付いているブランチが、現在のブランチです。

良いブランチ名は、わかりやすく、簡潔です：
- `add-readme`
- `fix-intro-typo`
- `update-version-number`

---

## 2. ブランチ上で変更をコミットする

モジュール5と同じように作業します：

```bash
# ファイルに変更を加える
git add .
git commit -m "変更内容の説明"
```

あなたのコミットは今、自分のブランチ上にあります——`main`上ではありません。
`main`は変更されていません。

---

## 3. GitHubにプッシュする

次に、自分のブランチをGitHubに送信します：

```bash
git push origin 自分のブランチ
```

最初の1回目は、GitHubアカウントの確認を求められます。
プッシュ後、そのブランチはGitHub上に存在します——他の人にも見えるようになります。

---

## 4. プルリクエストを開く

**プルリクエスト（PR）**とは、「自分のブランチをmainにマージしたい」という提案です。

GitHub上で：
1. `git-garden-playground` リポジトリに移動します
2. 黄色いバーが表示されます：「my-branch — Compare & pull request」
3. それをクリックします
4. 説明を書きます：
   - 何を変更したか？
   - なぜ変更したか？
   - レビュアーが知っておくべきことはあるか？
5. **「Create pull request」**をクリックします

![GitHubでプルリクエストを作成する](images/pull_request_aanmaken.png)

プルリクエストは、フォームではなく対話です。
説明が良いほど、レビューはスムーズに進みます。

---

## 5. 共同作業のワークフロー

```
main（安定版）
 |
 ├── ブランチA（Developer Aがここで作業）
 |        → コミット → プッシュ → PR → レビュー → マージ
 |
 ├── ブランチB（Developer Bがここで作業）
 |        → コミット → プッシュ → PR → レビュー → マージ
 |
main（マージ後に更新される）
```

全員が自分自身のブランチで作業します。
`main`は、承認されたプルリクエストを通じてのみ更新されます。
こうすることで、`main`は常に安定した状態を保てます。

---

## 6. 他の人の変更を取り込む

誰かのブランチがマージされたら、あなたもその変更を取り込みたくなるでしょう。

```bash
git switch main
git pull
```

`git pull`は、GitHubから最新版の`main`を取得します。

ローカルのファイルを変更せずに、GitHub上の状態だけを確認したい場合は？

```bash
git fetch
git status
```

`git fetch`は情報を取得するだけです。`git pull`は情報を取得し、*さらに*ファイルも更新します。

---

## 7. 実践課題

1. `git-garden-playground` リポジトリをクローンします（まだの場合）。
2. 自分の名前でブランチを作成します：`bijdrage-[あなたの名前]`
3. `bijdragen/` フォルダの中にファイルを作成します：`[あなたの名前].md`
4. その中に、次のことを書きます：
   - Gitから何を学びたいと思っているか
   - まだ残っている疑問を1つ
5. わかりやすいメッセージをつけて、そのファイルをコミットします。
6. ブランチをGitHubにプッシュします。
7. 簡潔な説明を添えて、プルリクエストを開きます。

課題が終わったら：講師またはクラスメートがそのPRをレビューします。
